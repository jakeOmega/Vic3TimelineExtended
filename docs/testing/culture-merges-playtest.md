# Culture merges play-test checklist

What the next play-test of the culture merges should look at. Since 2026-10-12 the owner's in-game checks no longer gate a merge: a PR lands on the offline gate (CI, the audits, the tests), adds what only the game can show here, and the play-test before a release works through the list. Where a build rests on an engine fact nobody has verified, it ships the preferred version with a `TE_SELF_CHECK` line in `debug.log` and names its fallback below; a BROKEN line means swap the fallback in.

Design: `docs/superpowers/specs/2026-11-07-culture-merges-design.md`. Mechanics, by task: `.superpowers/sdd/2026-11-07-culture-merges/` (not committed) and `docs/systems/mod_systems/culture_merges.md`.

## How to run

- **Deploy** per CLAUDE.md, "Play-testing unmerged work" (or from `main`). Check the playset has no Workshop copy of the mod.
- **Rule.** `culture_merges_rule`: Enabled or Disabled (the default since 2026-11-08: switch it on at game setup, or the system never runs). Game rules can change mid-game, from the change-country screen, so every item names its setting.
- **A new game.** A save begun before #1509 (2026-11-08) has no object for the 21 `cm_` cultures, so their merges never start there (`exists = cu:<r>` in `is_candidate`); one that started a merge on an earlier build holds an empty primary culture and floods `error.log` with `Culture  (-1)` lines from vanilla's culture triggers. Test in a game started on this build. On the first launch, `grep -c "Culture  (-1)" error*.log` should read 0, and `Missing expected culture static modifier` should not appear. If in a new game no country ever becomes a merge's candidate once its technology is known, suspect the `exists` guard first.
- **A game that reaches a merge.** An observer game from 1836, run to the technologies (Pan-Nationalism for tier 1, Mass Media for 1b, Television for tier 2). The German merge is the quickest to read: North German and South German are its core parts, Alemannic and Eastern German optional ones. Any candidate whose sphere holds most of both qualifies; option D shows which.
- **Console.** Vic3's console has no `effect` command: the menu is `event te_debug_cm.1`, on the player's country. A runs the census now, B runs this country's conversion now, C runs the dominance step and so the switch of every part at or over the threshold, D logs every `te_cm_` variable of this country's merges (`TE_CM_DEBUG`). Every option waits for the rule.
- **Logs.** Read `debug.log`, not `error.log`. Grep it for `TE_SELF_CHECK` first, then `TE_CM_DEBUG`. `debug.log` rolls over at 512 KB: copy the lines out as they appear.
- **After a vanilla `debug.log` flush,** a once-a-game check whose line was lost cannot fire again in that save. Start a new game, or rename its latch (`te_cm_chk_<name>_done`) in the save's variables.

## Self-checks

Nine checks, each a once-a-game line behind a latch global, all TEMPORARY: `common/scripted_effects/te_culture_merge_selfcheck_effects.txt`, `common/on_actions/te_culture_merge_selfcheck_on_actions.txt` and seven one-line hooks (listed in that file's header). Delete them after the 1.3.x play-test. Seven wait for the rule (`te_cm_system_enabled`), so none speaks in a game with no merges; Russification's reads a vanilla entry's INJECTed outcome, which has no rule gate, and the fervor copy's rides the copy, which has none either.

| Line | Means | Fallback if BROKEN |
|---|---|---|
| `TE_SELF_CHECK … cm_census_sane` | Once a game, at the first census of a part that a candidate's sphere holds in its homeland states. OK: the world's homeland pops (`home`) are above 0, the hold (`held`) is above 0 and at most 1, the sphere's pops (`sphere_pops`) do not exceed the world's, and the largest holder's count (`largest_holder`) is above 0, so a local written inside `owner = { }` reached the census and the acceptance scan's cut-off is real. BROKEN: `home` 0 (the homeland walk's sum never reached its global), `held` 0 or `sphere_pops` above `home` (a wrong denominator), or `largest_holder` 0 with pops above 0 (the owner-scoped write was lost). No line: no candidate held a part in its homeland states, or the rule is off; a game with no Pan-Nationalism has no candidates. A part with no owned homeland state is counted in the world instead and skipped, since its holders are noted in country scope and prove nothing about the owner-scoped write. | `largest_holder` 0: keep the largest holder in a global written by `te_cm_cp_note_holder` and reset at the top of `te_cm_census_part`, in place of the local. `home` 0: the census sums through locals across `every_scope_pop`; move the sums to globals. |
| `TE_SELF_CHECK … cm_acceptance_scale` | Once a game, at the first census of a candidate that has the part as a primary culture and at least a tenth of its pops in it. OK: its average acceptance of that culture (`country_average_culture_pop_acceptance`) reaches `te_cm_accept_open` (`acceptance_status_5`, 80); `acceptance_at_least` prints the rung it reaches among 100, 80, 60, 40 and 20 (a primary culture should read at the top). BROKEN: below `need`, so no part would ever pass its acceptance test, whatever the scale really is. No line: no candidate with a primary core culture and a tenth of its pops in it. | Read what the trigger returns for a primary culture from `acceptance_at_least`, and rescale `te_cm_accept_open`, `_close`, `_high_open` and `_high_close` in `te_culture_merge_values.txt`. |
| `TE_SELF_CHECK … cm_census_yearly` | Once a game: `START` at the first census, the verdict at the second, a year on. OK: `te_cm_census_year` advanced by exactly 1, so `global_var:te_cm_census_year < local_var:te_cm_year` guards the census once a calendar year. BROKEN: `gap` 0 (a second census ran in the same year, so the years-together counters would add several a year) or 2 or more (a year went by with no census; a rule switched off for a year in between reads the same, which is not the guard). No verdict: a `START` with no verdict after more than a year means the guard never lets a second census through. | Compare through a script value, `year` minus `global_var:te_cm_census_year`, tested above 0, in place of the variable-against-local comparison. |
| `TE_SELF_CHECK … cm_rate_inputs` | Once a game, in the first conversion pass of the merge's starter, on one accepted pop of the part in a homeland state (the base case the pace was tuned on). OK: the rate (`te_cm_pop_rate`) is above 0 and at most 0.5, and the line prints `literacy`, `urbanization`, `speed` and `rate`. The pace target of about 20 years assumes a developed state reads about 0.4 urbanization and a rate near 0.048; read the numbers, not only the verdict. BROKEN: rate 0 (a saved scope or a read did not resolve in the pop's scope) or at the 0.5 cap (an urbanization or literacy read on the wrong scale). No line: the starter has no accepted homeland pop of the part, or no merge has started. | Pass the part and the starter to the rate as variables on the pop's owner and have the value read them there; or compute the rate in `te_cm_convert_part` and pass `value = local_var:` to `change_pop_culture`. A urbanization reading far from 0.4 retunes `te_cm_urban_weight` and `te_cm_base_rate` (`test_culture_merge_values.py` pins the profiles). |
| `TE_SELF_CHECK … cm_conversion_merges_pops` | Once a game, over two conversion passes of one state: a state of a converting country that has pops of the part is counted for result pops before the first pass, 35 days after it (`after_first`), and 35 days after the next year's pass (`after_second`). OK: the second pass added fewer than half of what the first added (`second_pass` below half of `first_pass`), so `change_pop_culture` merged the converted share into an existing pop of the result and the pop count does not climb with every pass. BROKEN: it added about as many again, so every yearly pass splits off new pops until the switch. No line: for two years after a merge's first conversion pass; none if the first pass made no result pop in the sampled state (the sample starts over). | Convert in fewer, larger steps: run `te_cm_convert_part` every Nth year at N times the rate, so the pop count climbs N times slower; the spec accepts the bump (section 1). |
| `TE_SELF_CHECK … cm_switch_homeland` | Once a game, at the first switch, read on the monthly pulse 35 days later. OK: the part still has as many homeland states as before (`after` equals `before`), and every one is a homeland of the result, read through a saved scope (`by_scope`) and through `is_homeland = global_var:X` (`by_global`). BROKEN: `after` below `before` (`add_homeland` replaced the part's homeland), `by_scope` below `after` (it missed a state, for example one half of a split state region), or `by_scope` right and `by_global` below (`is_homeland = global_var:X` does not read a culture-valued global, which blinds `te_cmg_switched_part_kept` too). No line: no part has switched yet; run option C on a save where one is at the threshold. | `after` below `before`: add the part's homeland back after the result's. `by_scope` short: call `add_homeland` once per state region. `by_global` short: read the culture through a saved scope in `te_cmg_switched_part_kept`. |
| `TE_SELF_CHECK … cm_formation_keeps_primary` | Once a game, in `on_country_formed`, for a country that held a merge's result as a primary culture a monthly pulse earlier, read before the refresh puts anything back. OK: it still holds it. BROKEN: formation replaced its primary cultures. No line: no country with the result as primary formed a country, or formation hands the new country a fresh variable store, so the flag did not follow it (the formation hook's own `te_cm_converted_<m>` test is blind the same way; the monthly refresh is then the only path). | Nothing to change: the monthly refresh (`te_cmg_monthly_country`) and `te_cmg_formed_country` put the result back. |
| `TE_SELF_CHECK … cm_russification_outcome` | Once a game, on a country's monthly pulse. OK: `te_cm_russification_injected_fired` is set, so the engine took the INJECTed second outcome and concluded Russification through it. BROKEN: `te_cm_russification_complete` held for two monthly checks while `je_russification` stayed active, so the second outcome does not conclude the entry. An `INFO` line (not a verdict) says the entry ended with no marker after the trigger held: vanilla's own outcome, declared first, concluded it. No line: Russia has not completed Russification, or the vanilla outcome always wins when both hold; check `INFO`. | Add `je_russification` to East Slavic's `wait_for` in the config so the merge waits for the vanilla entry, and regenerate. |
| `TE_SELF_CHECK … cm_fervor_copy` | Once a game, at the first monthly copy of a switched culture whose merged culture has a fervor of 5 or more, read on the next global monthly pulse before that month's copy. The check sets the switched culture's fervor to 0, copies it through the ladder, and prints `before`, `target` (the merged culture's fervor), `zeroed`, `copied` (read straight after each set) and `later` (a copy later). OK: `target` at least 5 and `later` between `target` − 2.5 and `target` + 2, so the ladder set it (rounding down by under half a point) and the culture kept it for the month. BROKEN: `copied` near 0 (the ladder's `set_fervor` did nothing), or `copied` near `target` and `later` near 0 (the engine resets a culture with no pops). `zeroed` above 0 means a set applies after the read, so read `later` alone. If the check is BROKEN, the zero it set stays until the next copy, a month at most. No line: no culture has switched into a culture with fervor of 5 or more. No rule gate, like the copy. | The ladder did nothing: look for a load error on `set_fervor` and fix its form. The engine resets the culture: no copy can hold, so go back to the alternatives the owner offered (an injected outcome for German National Identity, which counts German fervor, and a wait on The Balkan League, or an on-action that adds the vanilla entry). |

## The rule off and on

- **Switch the rule off mid-game** (change-country screen) in a game with a running merge, and let a year pass. See: no `TE_SELF_CHECK` or census activity; the conversion stops; converted pops keep their culture; every `te_cm_` variable keeps its value (option D before and after).
- **Switch it on again.** See: the starter's entry comes back with its progress; a candidate's entry comes back (an inactive record returns, or the yearly net adds one); the census resumes; nothing started over. Do it once per kind: a candidate with an inactive record, a candidate with none, and a starter. `disable_evaluation` drops other countries' inactive records for good (`scripting_best_practices.md`), and nothing documents bringing one back after an off to on flip, so the net (R20) is what this checks.
- **A starter's entry** when the rule was off for years: the bar shows the real share again after one monthly pulse.

## The journal entry

- **Layout.** An inactive record for a candidate, a running entry, a completed one. The explanation collapsed, the status row and bar open, per `docs/guides/gui_style_guide.md`. A candidate's inactive record shows the unmeasured status before the first census and then the first failing condition.
- **The start button's tooltip** prints each unmet condition, one `custom_tooltip` reason per line, though they are nested inside `te_cmg_<m>_can_start` (the paragraph in `scripting_best_practices.md` under "Scripted Button Gating"). If the tooltip shows raw conditions, the fallback is to inline the reasons in the button's `possible`.
- **The bar** moves: `set_bar_progress` is called through `scope:journal_entry` from the entry's monthly pulse with a variable (`te_cm_bar_<m>`). Read it a month after the start. After a revolution an inherited entry arrives empty and shows 0 until its first pulse.
- **The bar's text fits on the bar** ("Least converted culture: toward the switch at 60%"); it ran off the panel before 2026-11-08.
- **The "Will complete if" list** reads three plain lines (we run the merge, the core cultures have switched, every other culture that joined has), not nested "has the variable in question" checks.
- **The Culture Merge Speed hover.** In a running merge's status line, hovering "Culture Merge Speed: +N%" shows the modifier's breakdown by source and the line naming what raises it. No mod status line had an inline hover before; if the text shows the raw `#tooltippable` markup or no hover, the fallback is to drop the hover and add the breakdown to the entry's reason text.
- **The AI presses the button** the day it can: count the starts in an observer game; two AI candidates for one merge must start it once. Watch for a country that starts a merge it cannot finish.
- **`status_desc` cost.** About 30 rows per entry, all variable reads, re-evaluated each frame. Open the Journal on a country with three entries and watch the frame rate.
- **A lower merge whose result switched first.** Anglophone can take `british` while no part has ever joined the British merge (R33), and once `british` switches into `cm_anglophone` the British merge can never start. See: a British candidate's entry concludes silently (the hidden invalid outcome, R36) and leaves no start button behind. The same holds for British, American and Platine once every alternative of one of their core slots has switched into a higher merge (`te_cmg_<m>_core_left`, R38).
- **Placeholder icons.** All 32 entries borrow vanilla's waving flag; a follow-up issue tracks the art.

## Starters, civil wars and releases

- **Dead-starter release.** Annex or conquer a running merge's starter. See: at the next yearly pass the merge returns to idle (state 0), the joined parts and counters stay, and another country that qualifies can start it and carries on from where it stood. A complete merge is never released. This is also the read of the forms the release rests on, for a starter whose country has since died: `exists = global_var:te_cm_starter_<m>`, `global_var:X ?= scope:Y`, `this = global_var:X` and `is_country_alive` on it. A merge stuck in state 1 with a dead starter means one of them reads wrong.
- **A civil war's winner inherits `te_cm_started_<m>`** (a revolution's winner keeps the loser's variables, not its modifiers or lists). Let the starter lose a revolution. See: the winner's inherited entry is active, the winner takes over the merge at the next yearly pass (`te_cm_starter_<m>` points at it), the conversion continues, and no second starter appears. Option D shows `we_are_starter` and `started` on the winner.
- **The old tag survives.** If the loser's tag survives while a flag holder lives, the winner's inherited entry sits active with no outcome until the old tag dies: record what the panel shows and for how long.
- **Re-adding a concluded entry after a release.** A starter that lost the merge to a release has its entry concluded; when it starts the merge again, does `add_journal_entry` bring a concluded record back? The yearly net relies on it only for a running merge's starter.
- **A complete merge whose starter is conquered** takes no late joiners (known limitation; a civil war is covered above), and at the next yearly pass lets go of every part it was still converting (R38). See: option D shows no `te_cm_joined_<m>_<c>` or `te_cm_in_<c>` left for those parts, and a higher merge that was waiting on this one (Pan-Slavic on a dead Yugoslavia while Slovene converted) can start.
- **Waits on vanilla entries are global (R37).** A merge does not start on a core part, and a part does not join, while any country has a wait-listed vanilla entry active: East Slavic on the two renaissances, American on the Civil War entries. (German's wait on `je_german_unification_idea` and Yugoslav's on `je_the_balkan_league` gave way to the fervor copy, below.) See: with a renaissance active in a country, Russia's East Slavic entry shows the wait and the Start button lists it; option D shows `te_cm_wait_years_east_slavic` rising once a year; when the last holder's entry concludes, or after 20 years, the wait lifts. Check `has_journal_entry` on a global-situation entry such as a renaissance: if it reads false for a country whose panel shows the entry open, the wait never holds and the East Slavic merge is not protected.
- **Fervor follows the merged culture (owner, 2026-11-07, R41).** Once a month (the global `on_monthly_pulse`, no rule gate) every culture that has switched takes the fervor of the culture it switched into, rounded down to the half point through a ladder of literals (`te_cmg_set_fervor_from_source`); at the switch the merged culture takes the part's fervor where its own is lower. Ukrainian and Byelorussian are left out. The self-check `cm_fervor_copy` says whether the copy holds. See, after the German merge switches North and South German: in the culture panel, North German's fervor equals German's (to the half point) from month to month instead of drifting toward 0; German National Identity (`je_german_unification_idea`) still completes, on German fervor; the German national movement (`movement_german_national`, creation above 10 on North or South German fervor) can still form. After the Yugoslav merge switches Serb, the Balkan League's start condition reads Serb fervor at Yugoslav's. After East Slavic switches Ukrainian before its renaissance has opened, Ukrainian's fervor drifts toward 0 and the Ukrainian Cultural Renaissance never opens (it needs Ukrainian fervor 15); the same for Byelorussian at 20. On first load, grep `error.log` and `debug.log` for `set_fervor` or `Malformed token` at `te_culture_merges_generated_effects.txt` and `te_culture_merge_effects.txt`. Also watch for side effects on a culture with no pops and a copied fervor above 25 (`CULTURAL_FERVOR_NATIONAL_AWAKENING_THRESHOLD`): a national awakening for it would touch no pops, but note any event or tooltip it raises.

## The census and the gates

These read forms the offline checks cannot run.

- **Numeric `global_var:te_cm_state_<m> ?= 1`** (and `te_cm_joined_`, `te_cm_in_`) in every generated trigger; the numeric global form has no precedent, only the numeric `var:X ?= N` and the scope `global_var:X ?= scope:Y` do. Every generated state read depends on it: a game where no entry ever leaves idle points here. Option D prints the state.
- **`te_cm_in_sphere` from state scope** through `owner = { }`, inside `cu:X = { every_scope_homeland_state }`; and `every_scope_homeland_state` itself in culture scope. `cm_census_sane` covers the owner-scoped write, not the sphere test: the census should find holders (`held` above 0 for a part the sphere holds).
- **`state_region = { is_homeland = cu:<c> }`** as a state limit inside `every_scope_state`, which the R26 walk and the pause test use.
- **The R26 result-SoL walk's cost.** It runs one `every_scope_state` pass over every sphere country, with an `is_homeland` test per core culture, but only once no core part has a figure, and only while an optional part whose gate is on (`te_cm_ok_<m>_<c>` 1) has not switched (R38). Time it once on a late save with Anglophone or Pan-Slavic complete.
- **The pause's meaningful share** is 0.10 of the part's pops in its homeland states, not of the sphere's holding. Look for a country that is paused although it holds a sliver, or not paused though it discriminates.
- **A bloc member that discriminates** pauses its own conversion only, and the part's gate still holds.

## Conversion and the switch

- **`change_pop_culture` with a named script value** (`te_cm_pop_rate`, pop scope, reading `scope:te_cm_part` and `scope:te_cm_starter`) as `value`: vanilla passes literals; its sibling `change_pop_religion` takes a script value. See: pops in the starter's homeland states lose the part's culture a few percent a year (`cm_rate_inputs` prints the rate). If nothing converts, the value read 0 in the engine's `change_pop_culture` argument.
- **Fractional splitting** and merging, `cm_conversion_merges_pops`. Also watch the pop count in the biggest converting state across the run: it should not double.
- **The pace.** A developed starter that holds all of a part's homeland reaches the switch in about 20 years; a slow one, about 40. Note the urbanization `cm_rate_inputs` prints.
- **A hold near 60%.** For a new culture, dominance can't pass the sphere's hold, and the switch (60%) equals the hold that opens a merge, so a sphere holding just over 60% of a part's homeland finishes only slowly (at 80% the switch takes about 28 years on the developed profile, at 70% about 40) and one that slips below 60% can't finish until it gains ground (owner, 2026-11-07: that is the lever, not a stall). Look for a running merge whose least converted part levels off below 60%; record the merge, the sphere's hold (option D, `te_cm_held_<m>_<c>`) and the years it has run, to judge whether the pace feels right.
- **`global_var:X ?= cu:Y`** (a culture-valued global compared with a `cu:` literal) in the homeland-chain helpers `te_cmg_remove_parts_of_<culture>`: vanilla's form is `?= scope:Y`. See: remove a result's homeland by Dynamic Homeland Progress after a switch and watch each part that switched into it lose its homeland in the same step.
- **A global written earlier in an effect read later in the same effect** (`te_cm_switch_part` writes `te_cm_switched_<c>`, then `te_cmg_<m>_core_switched` reads it to complete the merge). See: the merge's state turns to 2 in the same pass as its last core part's switch.
- **The templated trigger name** `te_cmg_$MERGE$_core_switched = yes` inside an effect's `limit` (the `te_cm_tier_tech_$TIER$` dispatcher is the precedent).
- **`set_global_variable … value = scope:te_cm_result`** and **`is_homeland = global_var:X`** where the variable holds a culture: `cm_switch_homeland` covers the second.
- **A switch reaching a foreign-held homeland.** After a switch, open the state panel of a state of the part's homeland that another country holds. See: the result's homeland is listed there as well, though the owner is not in the sphere.
- **A kept part homeland with no pops** shows nothing but its listing in the state panel: no tooltip noise, no event, no map effect beyond the homeland line. The part's homeland stays while the result's is in the state, and Dynamic Homeland Progress takes both together.
- **The result's primary culture.** The starter has it from the day the merge starts; a bloc member gets it only where a part it converts is primary there (R34). Check a subject with a sliver of the part: its pops convert and it gains no primary culture.
- **Bavaria released after the switch.** Release Bavaria as a country after German has switched. See: it has no North German or South German primary but the result gets added within a month (`te_cmg_monthly_country`), since a released country may not run `on_country_formed`; its pops are German, not the old parts. Note that `on_country_formed` for a released country (and `on_country_released_as_independent`) may not fire.
- **A formed country.** Prussia forms Germany mid-merge. See: the result is still a primary culture of Germany (`cm_formation_keeps_primary`), the entry follows, and the conversion goes on.
- **Chained merges (R33).** Italian before Latin, French before Latin, American before Anglophone: the higher merge waits until the lower one is complete with every joined part switched, or has no part joined. A merge whose result has switched into a higher merge joins and converts nothing more. Once the higher merge has joined the lower result, the lower merge takes no new parts (R38): with Latin running on `french`, a Catalan that qualifies for French stays out (option D shows no `te_cm_joined_french_catalan`), so Latin's French slot doesn't stall. Latin's Platinean slot takes `cm_platine` once Platine is complete.
- **Demonyms.** The `cm_` cultures are not on vanilla's demonym ladders, so a plural may render as the singular. Look at an event or the country list that names a merged people.

## Content that loads

- **The expected static modifiers.** The engine expects six static modifiers of every culture (`<culture>_standard_of_living_modifier_positive` and its kin, vanilla's `07_`, `10_` and `11_` static modifier files); the generator writes them for the 21 results (`te_merged_culture_static_modifiers.txt`). See: no `Missing expected culture static modifier` line in `error.log` at load (126 before, 2026-11-08). Whether a result culture's object is complete without them is unknown; if a new game still logs `Culture  (-1)`, that, not the old save, was the cause.
- **Merged traits** load from the mod's own `discrimination_traits` file (`te_merged_culture_traits.txt`), though vanilla splits its heritage and language traits across two files. See: the new cultures' traits (for example `heritage_cm_latin`) show in the culture panel, and `debug.log` has no unknown-trait line at load.
- **The `cm_` cultures in the culture lists.** Open a culture picker or the pop panels' culture filter. See: the 21 result cultures listed beside vanilla's, with names and colors, though they have no pops until a merge converts some.
- **Files that iterate every culture now see 21 empty cultures.** Twenty-four files do (`common/ai_strategies/other.txt`, `common/decisions/extra_decisions.txt`, `common/diplomatic_actions/extra_diplo_actions.txt`, `common/ideologies/modified.txt`, the opium and turtle island entries, `extra_on_actions.txt`, the party weights, the bloc names, three script value files, four scripted effect files, five scripted trigger files, `108_cultural_exchange.txt`, `decolonization_events.txt` and `extra_law_events.txt`; the full list is in Task 2's report). Irredentism, heritage and tourism, and cultural hegemony are the likely ones to divide by a culture's pop count or list every culture. See: no division-by-zero lines in `error.log`, no empty entries in a list a player reads.
- **Demonym plurals of the `cm_` cultures.** Vanilla's four demonym ladders (`getPluralDemonym`, `getSingularDemonym` and the two female forms, in `common/customizable_localization/demonyms_custom_loc.txt`) key each culture as `cu:<c> ?= this` and end in an unconditional `*_DEFAULT` entry that prints the culture's own name, so the 21 result cultures read as their own singular where a plural is meant ("German" for "Germans").
