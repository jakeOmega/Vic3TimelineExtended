# Dynamic Modifier Pattern

Part of the [mod systems reference](../mod_systems.md), which indexes every system.

## Dynamic Modifier Pattern (`add_modifier` with `multiplier`)

Several mod systems use a common pattern for continuously-scaling modifiers:
1. Define a **static modifier** in `common/static_modifiers/extra_modifiers.txt` with base values (e.g., `country_construction_goods_cost_mult = 1`).
2. Define a **script value** in `common/script_values/extra_script_values.txt` that computes a multiplier (0 to N).
3. In an **on_action** (`on_yearly_pulse_country` or `on_yearly_pulse_state`), remove the old modifier and re-apply with `add_modifier = { name = X multiplier = <script_value> }`.
4. The engine multiplies every field in the static modifier by the multiplier value.
5. If the modifier applies only under some conditions, re-check them on every refresh and remove it on the refresh they fail. A gate of the form `OR = { <conditions>  has_modifier = X }` never looks at the conditions again once X exists, and with a decay floor such as "last value ÷ 1.2" the value never reaches 0. Excess Private Construction shipped that way and lingered for about a century (fixed 2026-09-26). And don't gate a sink on a quantity the sink itself drives, such as the sign of net income: the modifier then removes itself as soon as it works. Keep it on a need it can't change (§ Excess Private Construction).
6. A state modifier that is only bookkeeping stays out of the state panel's modifier rows: give it `icon = gfx/interface/icons/timed_modifier_icons/modifier_system.dds` (the mod's one invisible modifier icon), add its key to both rows' name filter in `gui/states_panel.gui` (`EqualTo_string(TimedModifier.GetName, Localize('<key>'))`; a GUI can't compare a timed modifier's icon, `gui_modding_guide.md` gotcha #40), and add one `has_modifier` term for it to `gui_state_hidden_modifier_count` (`common/script_values/gui_chart_script_values.txt`). Its effect still shows in the Modifiers tab and the breakdown tooltips. `test_hidden_state_modifiers.py` fails on a modifier with that icon missing from either. A state modifier that a state panel card already shows is left out of the rows the same way but keeps its icon: the Grand Monument card's `gm_local_*` (the test's `SHOWN_ON_A_CARD_PREFIXES`) and the Wealth Concentration tile's six `inh_` state modifiers (`SHOWN_ON_A_CARD_NAMES`). Hide one only where its card shows whenever the modifier is there: the Demographics subtab is gone while the Demographics rule is off, so the Wealth Concentration six, which run under every rule, have a tile in the state panel instead. The nine standing census modifiers (Inequality, Youth Bulge, Fewer Men, More Men, the Longevity Gap, Metropolis, Dispersed Towns, Primate City, Provincial Neglect; `SHOWN_ON_THE_DEMOGRAPHICS_TAB_NAMES`) are listed in the subtab's Modifiers section (`te_state_demog_modifiers`; `gui_state_demog_modifier_count` gates its "none" line) and hidden from the rows (owner, 2026-10-21): they exist under Full only, which runs the census and so the subtab. The timed ones a choice grants (Planned Capital, the event wave's options) stay in the rows with their time left. One edge: switching the rule from Full to Disabled leaves them on their states, hidden, until each state's next yearly pulse takes them off.
7. A country modifier with no duration needs a line in the Nation tab's registry (`scripts/generators/gen_nation_tab.py`; § Nation Tab), which decides whether the country panel's list shows it.

Systems using this pattern:
- **Global Warming** — `global_warming` modifier × `temperature_anomaly_display` (applied from JE `on_monthly_pulse`)
- **Construction Cost Scaling** — `construction_cost_scaling` modifier × `construction_cost_scaling_mult` (applied yearly, country scope; GDP part × the share that applies, from slack)
- **Migration Crowding** — `migration_crowding` modifier × `migration_crowding_mult` (applied yearly, state scope)
- **Excess Private Construction** — `too_much_private_construction` modifier × `var:too_much_private_construction_cached`, set yearly from `too_much_private_construction_script_value` (country scope; § Excess Private Construction)
- **Tourism** — `tourism_output` × `total_tourism_output_bonus_percent` and `tourism_throughput` × `total_tourism_throughput_bonus_percent` (state scope), re-applied by `te_update_tourism_modifier` from `tourism_on_action` on `on_monthly_pulse_state`, because its inputs (`city_size_rank`, the state's infrastructure balance, building levels) move monthly. Uses ~2700 lines of state_region appeal values in `common/script_values/tourism.txt`. **Heritage (tourism heritage spec 2026-10-23):** `tourism_bonus_from_base_appeal` is the score less `tourism_heritage_moved` (floored at 0), the points each state's monuments stand for, from `common/script_values/tourism_heritage_generated.txt` (`scripts/generators/gen_tourism_heritage.py` over `scripts/generators/data/tourism_heritage_moves.csv`; `--annotate` notes each move on its score). A move counts only while its monuments can exist: a vanilla wonder's always, a landmark's while `gm_system_enabled` and `gm_landmarks_seeded`, a To History landmark's while `gm_system_enabled` and `gm_landmarks_seeded_2` (set with the 1836 seeding since phase 2, so a save from before it keeps those points), a site's while `gm_system_enabled` (seed round 4 gives an older game the To History sites). 93 states move 2,280 points; a dug site's points come back as its monument's tourism. Zero-point rows keep the revisit, pilgrimage and townscape lists for pass 2. National Parks read the raw score. Monuments are an output source, `tourism_bonus_from_monuments`: +0.10 per `bg_monuments` building, and the 1836 wonders the points their states moved to them (Taj Mahal 0.40, Angkor Wat 0.30, Hagia Sophia, Vatican City, Forbidden City, Saint Basil's and White House 0.20, and the Djenné mosque 0.20 once rebuilt, in Eastern Mali, the only state vanilla lets it stand in); the Skyscraper keeps +0.10 throughput (`tourism_throughput_from_skyscraper`). The infrastructure source, `tourism_throughput_from_infrastructure`, is `E / (E + 30000)` with E = vanilla's `state_infrastructure_balance` (infrastructure less usage) floored at 0: diminishing returns toward a +100% ceiling, +50% at 30,000 spare (it replaced per-level Port, Railway and Highway tiers that topped out at +36%, +18% and +18%). The 30000 half-point is the owner's figure, not measured against a late-game save; check it at the next play-test (`docs/testing/tourism-playtest.md`). It must run from a state pulse: law, treaty and building hooks have unreliable scope chains for state-targeted script values.
