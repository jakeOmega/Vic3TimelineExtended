# Culture Merges

Part of the [mod systems reference](../mod_systems.md), which indexes every system.

Spec: `docs/superpowers/specs/2026-11-07-culture-merges-design.md`; plan: `docs/superpowers/plans/2026-11-07-culture-merges.md`; play-test list: `docs/testing/culture-merges-playtest.md`. The build departs from the spec in places (the roster rulings, the completion rule, chaining, where the result becomes primary, and, since 2026-11-09, a switched part leaving the primary cultures where the spec kept it for good); this file and the script describe what was built.

## Culture Merges System

- **What:** a country that holds most of a set of closely related cultures (North and South German), treats them as equals and has the tier's technology starts a merge. Each year a slice of every joined part's pops in its sphere becomes the result culture (`cm_german`). Once the result holds 60% of the result-plus-part pops in a part's homeland states, every remaining pop of that part, anywhere in the world, switches at once. 32 merges, all generated from one roster.
- **Sphere** (`te_cm_in_sphere`, against `scope:te_cm_starter`, which every caller saves first): the starter, its subjects at any depth (`is_subject_of`), and, when the starter leads a power bloc, the bloc's members (the list includes the leader). A member of a bloc the starter only belongs to is outside it.
- **Tiers are numbers in script:** 1 = the spec's tier 1 (same language and heritage; Pan-nationalism), 2 = tier 1b (same language across heritages; Mass Media, very high acceptance, 30 years together), 3 = tier 2 (same language family; Television, the component merges complete, 50 years together). `te_cm_tier_tech = { TIER = n }` dispatches to `te_cm_tier_tech_1/2/3`. A tier belongs to a part, not to the merge (R17): the merge starts on its core parts' tiers, and each part joins on its own tier's conditions, even one below the merge's (Polish joins Pan-Slavic at tier 1).
- **Life cycle**, the global `te_cm_state_<m>`: 0 or missing = idle, 1 = running, 2 = complete (every joined core part has switched). A complete merge stays open for late joiners and is never undone.
- **Journal entry** `je_te_cm_<m>` (generated; group Domestic Affairs; title "Cultural Merge: <result>"; `can_revolution_inherit = yes`, `can_deactivate = no`). Shown inactive to a candidate (`te_cmg_<m>_is_candidate`: for a new result, the result culture exists in this game (`exists = cu:<r>`: the engine makes a culture's object when a game starts, so a game begun before the culture was added has none, and a merge started there added that empty culture as a primary culture; a 1883 save from before #1509 then logged about 8,700 `Culture (-1)` lines in two hours, 2026-11-08; `can_start` repeats it in a `hidden_trigger`); a core culture or the merge's own result is primary (the result since 2026-11-09: a switched core part leaves the primary cultures, so after a merge returned to idle the result is all a country may have left of them), the start tier's technology is researched, the merge isn't complete, its result hasn't switched into a wider merge (R36), and, for British, American and Platine, every core slot still has an alternative that hasn't switched into another merge, `te_cmg_<m>_core_left` (R38)); `possible` is `te_cmg_<m>_can_start` or `te_cmg_<m>_is_starter`, the latter in a `custom_tooltip` (`te_cm_tt_done_starter`): bare, the page printed its script and logged a nullptr promote for the empty starter on every redraw (2026-11-09). An inactive entry's page shows this `possible` list, each condition checked or not, and no status row; so the gap condition (`te_cmg_<m>_sol_tt`, behind a `trigger_if` on `te_cm_sol_gap_<m>`, else the generic `te_cm_tt_sol`) names the best- and worst-off core cultures, their figures and the gap too. The start button `te_cmg_start_<m>_button` ("Begin the <result> Merge", `ai_chance = 100`, so the AI starts any merge it can on the day it can) runs `te_cmg_start_<m>`. The bar `te_cmg_<m>_bar` ("Merge Progress", its text a short label, since the bar draws it on one line: `gui_modding_guide.md` gotcha 49) shows the lowest dominance over `te_cm_switch_share`, capped at 1 (`te_cmg_<m>_progress`), over the joined core parts while the merge runs, and over every joined, unswitched part once it is complete; so it is full at the switch, while the running row prints the dominance itself. The entry's monthly pulse writes it through the display cache `te_cm_bar_<m>`. `status_desc` is a `first_valid` ladder: the rule off (first, since `is_candidate` needs the rule and a starter's merge pauses with it), complete, late (complete, a late part still converting), running, another starter, not a candidate, unmeasured (before the first census), then the first failing start condition (a component; per core slot: busy, or for a slot only another merge's result fills, still forming there, then hold, acceptance, years, and in Pan-Turkic's mixed core the part's own technology; the standard-of-living gap, which names the best- and worst-off core cultures, their figures and the gap from the last census (`_status_sol_wide`; a gap already under the open value with the gate still shut, `_status_sol_close`, says the next census counts it, since a slot was unmet at the last one; no figure at all, the shared `te_cm_status_sol`); a wait), ready, pending. All 32 entries borrow vanilla's `waving_flag.dds` until their icons are drawn (`test_icon_pipeline.py` excepts exactly them).
- **Outcomes:** complete (gold) for the starter once the state is 2 and `te_cmg_<m>_all_switched` holds (every joined part, core and optional, has switched; R5). A hidden invalid outcome ends the entry of a country that is not the starter while another country runs or finished the merge; for the eleven merges whose result is a part of a wider merge, once that result has switched (R36); and for British, American and Platine, once `te_cmg_<m>_core_left` fails (R38). There is no outcome for "the rule is off" (R27). A part that joins after the entry concluded converts and switches with no entry.
- **Starting** (`te_cm_start_merge`): state 1, the global `te_cm_starter_<m>` = this, the country flag `te_cm_started_<m>`, the result added as a primary culture. Then `te_cmg_<m>_join_ready` joins every slot culture that passes `can_join` and isn't waiting (`te_cm_join_part`: `te_cm_joined_<m>_<c>` = 1, `te_cm_in_<c>` = the merge's 1-based index). Late parts join at each census (`te_cmg_<m>_settle`, the starter only), whether the merge is running or complete.
- **Starters and civil wars** (R30): `te_cmg_<m>_is_starter` is the global starter, or a holder of `te_cm_started_<m>` while the global starter is dead or missing. A revolution's winner inherits the flag (variables cross, modifiers and lists don't) and continues the merge. Each census first runs `te_cmg_release_lost_starters`: a gone starter is re-pointed to a living flag holder, and a running merge with none returns to idle (`te_cm_release_starter`: state 0, starter global and flags removed, joined parts and counters kept, so the next starter carries on from where it stood). A complete merge is re-pointed but never released; one still without a living starter after the re-point lets go of every joined, unswitched part (`te_cm_unjoin_part`: `te_cm_joined_<m>_<c>` removed, and `te_cm_in_<c>` where it holds this merge's index), so `all_switched` holds again, the parts are free for any other merge that lists them, and a higher merge's slot for the result opens (R38). Pops converted so far stay converted. Until the next census re-points it, a winner converts nothing (at most a year, accepted).
- **The entry net** (R20): `settle` adds the entry, guarded by `NOT = { has_inactive_journal_entry }` (`test_add_journal_entry_guard.py`), to an idle merge's countries that pass `can_start` and to a running merge's starter that lacks it. A rule switched off and on lets `disable_evaluation` drop other countries' inactive records for good, and this brings them back. It never re-adds a complete merge's entry: the record would conclude again and re-fire the outcome.
- **Game rule** `culture_merges_rule`: `culture_merges_enabled` and `culture_merges_disabled` (the default since 2026-11-08), read through `te_cm_system_enabled` (`has_game_rule = culture_merges_enabled`, so a save that stored no value, one begun before the rule existed, stays off). Off by default because such a save has no object for the 21 new result cultures, so a merge into one added an empty primary culture (#1518; the `exists` guard below stops that too). The default can turn on once most running games began with the cultures; keep the gate positive then, since those older saves still lack them. A rule can change mid-game, from the change-country screen. Off pauses everything (census, conversion, switch, monthly upkeep, formation hook, buttons, and the entries through `disable_evaluation`) and resets nothing; on resumes every merge where it stood (R19). Converted pops keep their culture. The laws, technologies and institution that speed merges keep their other effects. Every other rule-pruned entry ends on its rule (2026-11-08); the generated merge entries carry `# REVIEWED 2026-11-08 (rule_outlives)` on their `disable_evaluation` line, which `test_journal_entry_shape.py` accepts in place of an invalid outcome.
- **Speed modifier** `country_culture_merge_speed_mult` ("Culture Merge Speed", percent, `te_culture_merge_modifier_types.txt`), so its tooltip lists every source: Public Schools +10% (`te_culture_merge_law_injections.txt`), Ministry of Culture +5% per level (in place in `extra_institutions.txt`, a mod institution), Radio +10%, Film +5% and Mass Propaganda +10% (`te_culture_merge_tech_injections.txt`). The running row shows the starter's total (`te_cm_speed_display`, kept in `te_culture_merge_display_values.txt` because `test_culture_merge_values.py` reads every value of the numbers file as a number).
- **Debug:** `event te_debug_cm.1` (`events/te_debug_cm_events.txt`; helpers in `te_debug_cm_effects.txt`): A runs the census now (no lock or year guard, so a second run in a year adds a second year to the counters), B this country's conversion, C the dominance step and so every due switch, D logs every `te_cm_` variable of this country's merges as `TE_CM_DEBUG` (generated `te_cmg_debug_dump`), and for a merge with a bespoke gate a `gate` line (`te_cm_debug_dump_gate`, or `_gate_milestone` with the latch). Each call names only variables something sets, since a read of a name nothing sets logs `is used but is never set` at every load: `te_cm_debug_dump_merge_waiting` (with the wait counter) for East Slavic, American and Brazilian, the three merges with a core wait, `te_cm_debug_dump_merge` (`wait_years=-1`) for the rest, and each part's `sol_ok` is its own gate for an optional part and the merge's for a core part (`SOL_OK`). The other never-set reads, 28 names from the eleven absorb results' slots and Anglophone's wait counter, are tracked noise (`docs/audits/open_issues.md` L30). Thirteen once-a-game `TE_SELF_CHECK` lines check the engine facts the build rests on (`te_culture_merge_selfcheck_effects.txt`, `te_culture_merge_selfcheck_on_actions.txt`, thirteen one-line hooks), all TEMPORARY until the 1.3.x play-test; the play-test list gives each one's fallback.
- **Tests:** `test_culture_merges_config.py`, `test_gen_culture_merges.py`, `test_culture_merge_values.py`, `test_culture_merge_census.py`, `test_culture_merge_entries.py`, `test_culture_merge_switch.py`, `test_culture_merge_russification.py`, `test_culture_merge_selfchecks.py`, `test_culture_merge_mod_refs.py`, `test_culture_merge_primary_reads.py`, and `test_homeland_progress.py` for the homeland tie-in. Several run the generated triggers and effects through small interpreters (chains, the starter flag, the primary rule, completion).

### Culture merge variables

State lives in variables, never in modifiers or variable lists, so a civil war's winner keeps it. `<m>` is a merge key, `<c>` a culture id, `<r>` a result culture.

| Kind | Name | Meaning |
|---|---|---|
| global | `te_cm_state_<m>` | 0 or missing idle, 1 running, 2 complete |
| global | `te_cm_starter_<m>` | the running or complete merge's starter |
| global | `te_cm_home_<c>` | the culture's pops in its homeland states at the last census (world pops if it has no owned homeland state); for a joined part, the part's pops that remain |
| global | `te_cm_home_r_<c>` | for a joined part, the result's pops in `<c>`'s homeland states, world-wide (R22); first set at the census after the join, so read guarded |
| global | `te_cm_in_<c>` | index of the running merge the culture has joined; removed at its switch |
| global | `te_cm_joined_<m>_<c>` | 1 once the part has joined merge `<m>` |
| global | `te_cm_dom_<m>_<c>` | the result's share of result + part pops in `<c>`'s homeland states |
| global | `te_cm_switched_<c>` | the result culture (a culture scope) `<c>` switched into |
| global | `te_cm_census_year`, `te_cm_census_lock` | the year of the last census; a 330-day lock as backstop |
| global | `te_cm_russification_injected_fired` | set by the injected Russification outcome (the self-check's marker) |
| country | `te_cm_held_<m>_<c>` | the sphere's share of `te_cm_home_<c>` (0–1); for a joined part, sphere part + result over home + home_r |
| country | `te_cm_ok_<m>_<c>` | 1/0: hold and acceptance, with hysteresis; for a joined part, the hold alone (R29) |
| country | `te_cm_sol_<m>_<c>` | the part's pop-weighted standard of living over the same pops |
| country | `te_cm_sol_ok_<m>` | 1/0: the standard-of-living gap over the core parts (R23) |
| country | `te_cm_sol_best_<m>`, `te_cm_sol_worst_<m>` | the best- and worst-off measured core parts at the last census (culture scopes), for the status row; removed while no core part has a figure |
| country | `te_cm_sol_hi_<m>`, `te_cm_sol_lo_<m>`, `te_cm_sol_gap_<m>` | their standards of living and the gap between them, the figures the gate read; removed with them |
| country | `te_cm_sol_ok_<m>_<c>` | 1/0: an optional part's own gap gate (R23, R26) |
| country | `te_cm_years_<m>_<c>` | years held and accepted together (tiers 1b and 2) |
| country | `te_cm_wait_years_<m>` | years the merge has qualified while waiting for a vanilla entry |
| country | `te_cm_started_<m>` | 1 on the starter; inherited by a revolution's winner (R30) |
| country | `te_cm_paused_<m>_<c>` | 1 while this converting country fails acceptance of the part (R29) |
| country | `te_cm_converted_<m>` | 1 once this country has converted for the merge (the formation hook reads it) |
| country | `te_cm_bar_<m>` | the bar's display cache |
| country | `te_cm_tmp_cnt` | a holder's pops of the part, inside one `te_cm_census_part` call only |

## Config and Generator

- **Roster** `scripts/generators/culture_merges_config.py`, the single source: `Part(cultures, tier, wait_for, gate)` (a slot of alternative ids, usually one; Anglophone's second core slot is `("yankee", "cm_american")`, Yankee until the American merge finishes and its result afterwards, and Latin's Platinean slot `("platinean", "cm_platine")`. A merged part is represented by its result (R38): a slot culture that is a part of another merge with a `cm_` result accepts that result too, where the result can't already fill another slot of the merge (Pan-Slavic and Anglophone list Yugoslav and American as core parts). `RepresentationTest` in `test_culture_merges_config.py` lists every case.), `NewCulture(name, color)`, `Merge(key, result, new, core, optional, components, skip_if_dlc, gate)`, `Gate(trigger, milestone, clause, why)` (§ Bespoke Gates). 21 merges make a new culture (`cm_<key>`); 11 absorb their parts into an existing one (Hungarian, Dutch, Finnish, French, British, Brazilian, Chinese into Han, Japanese, Persian, Hindustani, Filipino), whose result is its first core part and is held and acceptance-tested only, never joined, converted or switched. Core parts are ordered largest first by 1836 pops, because the first supplies the result's fields.
- **Start tiers:** 26 merges at tier 1, Anglophone at 1b, and Latin, Pan-Slavic, Pan-Turkic, Pan-Malay and East African at tier 2. Pan-Turkic's core is mixed (Kazakh and Kyrgyz tier 1, Tatar 1b, the rest 2), so each core culture's own technology joins its slot's route in `core_ok` and `can_start` (R31).
- **Derived tiers** (`derive_tier`), measured against every other core slot: a shared language and heritage gives 1, a shared language 2, a shared language group 3, and no shared group is a validation error (a cross-family merge is a v1 non-goal). Hand-set where history disagrees with the traits: tier 1 for Occitan and French, and for Walloon (whose heritage would put it at 1b), Han with Yue, Hakka and Min, Japanese with Ryukyuan, Kannada, and Mazanderani (Tabari is its own language in vanilla); tier 3 for Catalan.
- **Roster rulings** against the spec's Appendix A: Turkmen is optional in Oghuz Turkic (R4: its heritage would make the whole merge 1b); Filipino drops the two Hispanophone cultures (R3: another family); Wallonian is optional in French (owner, 2026-11-09: its homeland is Belgium's, so as a core culture it held back France's whole merge, Occitan included, until France annexed Belgium or made it a subject; it still joins at tier 1); Persian takes Mazanderani (tier 1) and Baluchi (tier 3, from its traits) as optional cultures (owner, 2026-11-09: the appendix's row listed only the cultures sharing `language_persian`); the Nguni result is "Greater Nguni", since vanilla already names a culture Nguni; East African has no components (R1), so only its 50-year counter applies.
- **Components**, the tier-2 merges whose results are core parts: Latin (French, Italian), Pan-Slavic (East Slavic, Czechoslovak, Yugoslav), Pan-Turkic (Oghuz Turkic), Pan-Malay (Indonesian, Filipino). `can_start` requires each at state 2, and the result's slot is available only as R33 allows (§ The Switch).
- **Waits** (`wait_for`, per part, the vanilla journal entries that work on its culture): Ukrainian and Byelorussian on their renaissances; Dixie on `je_acw_reincorporate` and Afro-American on `je_acw_equality`, in both American and Anglophone; Sulista on `ragamuffin_war` in Brazilian (owner, 2026-11-09). A wait holds while **any** country has the entry active, since a switch breaks every holder's entry (R37), until `te_cm_wait_years_<m>` reaches `te_cm_wait_cap_years` (20). A waiting part doesn't join (`te_cmg_<m>_<part>_waiting` guards `te_cm_join_part` in the join-ready effect); only a core part's wait also holds the start (a `te_cmg_<m>_wait_<part>_tt` line in `can_start`). The counter adds a year per census (`te_cmg_<m>_settle`) while the rest of `can_start` holds and a core part's entry is open. So Anglophone, whose waits are all on optional parts, starts without waiting, and its Dixie and Afro-American stay out, with no cap, until the Civil War entries end (they time out); American's start waits on Dixie's entry only, and its Afro-American joins once Equality for All closes or the start waited the full 20 years. Two core parts on one entry would share one start condition and one status row (no merge has that now; `test_culture_merge_entries.py` pins it on a roster of one). German's wait on `je_german_unification_idea` and Yugoslav's on `je_the_balkan_league` gave way to the fervor copy (owner, 2026-11-07; § Compatibility).
- **`skip_if_dlc`:** the Brazilian merge runs only without `rp1_content`, whose own nation building converts the same cultures. Both `is_candidate` and `can_start` test it.
- **Helpers:** `merge_by_key`; `derive_tier`; `validate` (a culture vanilla lacks, a `cm_` id vanilla defines, a culture in two slots, a cross-family part, a bad component, a malformed color; a test keeps each new color clear of its parts' and the other results'); `parts_of(result)` and `successors_of(culture)`, the whole chain (`corsican` → `cm_italian`, `cm_latin`); `unwrap`, `culture_traits`, `trait_group`.
- **Generator** `scripts/generators/gen_culture_merges.py`, in `POST_LOAD_REGENERATORS` before `organize_loc` (`--check` exits 1 when stale, `--dry-run` writes nothing). It reads vanilla from the committed `vanilla_parsed/` cultures and discrimination traits, never the live ModState, which holds the generated `cm_` cultures and whose vanilla differs by machine. Outputs, one `render_*` each: the cultures, the traits, the six static modifiers the engine expects of each new culture (`te_merged_culture_static_modifiers.txt`, vanilla's shape, named in the generated loc; without them the engine logs `Missing expected culture static modifier` 126 times at load, 2026-11-08), the three modifier types those use (`te_merged_culture_modifier_types.txt`, which vanilla registers for every culture and the engine never creates; without them each static modifier logs `Unknown modifier type` and loads empty, 126 lines at the next launch), the loc, the triggers, the effects, the journal entries, the buttons, the bars and the values (`docs/auto_generated_files.md` names each file).
- **A new result culture:** color from the config; religion, graphics, ethnicities, obsessions, taboos, `name_format`, seal and `assimilation_rate` from the first core part; traditions are those every core part shares (none today; R13); name lists from every part in config order, deduplicated. A part without a gendered surname list lends its plain one, so only East Slavic and Pan-Slavic carry women's surnames. Heritage and language come from the first core part, except that a merge starting at tier 2 mints `language_cm_<m>` in the parts' shared language group, and `heritage_cm_<m>` only where its core parts share no heritage: Latin, Pan-Slavic and Pan-Turkic mint one, East African and Pan-Malay keep their shared vanilla heritage (R16), since a shared heritage trait is worth more acceptance than a shared group. A minted heritage takes its group from the first core part, so Pan-Turkic's is middle eastern (Turkish) though Kazakh and Kyrgyz are Kipchak. `CARRIED_FIELDS` names every field handled, and a test fails when a vanilla patch adds one.
- **Repeated keys:** the snapshot returns a key a block repeats (an ethnicity weight, `1 = arab 1 = slavic`; Marathi's name lists) as a list of `(op, value)` pairs. The readers expand them and raise on any shape they don't know; the first version printed Python reprs into four cultures (`docs/guides/python_tools.md` § Vanilla data source).
- **Why the `cm_` prefix:** a duplicate culture key is dropped (`Duplicated key X will not be created`), and the Workshop mod Syncretic Cultures defines `german`, so an unprefixed result would lose to it or knock its culture out depending on load order (`scripting_best_practices.md` § Top-Level Database Collisions).
- **Player-facing words:** "part" is the roster's word for a slot culture and never reaches the player. The text says "constituent culture" (or "culture" once that is clear), "core culture" and "optional culture" (owner, 2026-11-08); `test_culture_merge_entries.py` fails on "part" as a noun in the entry text, the `te_cm_*` phrases and the rule's description. The complete outcome's three conditions each sit in a `custom_tooltip` (`te_cm_tt_done_starter`, `te_cmg_<m>_done_core_tt`, `te_cm_tt_done_all`), since the panel's "Will complete if" list otherwise spells out the scripted triggers' variables. The running and late rows' Culture Merge Speed hovers to `te_cm_speed_tt`, the modifier's breakdown by source and what raises it.
- **Loc:** result and trait names and every entry, button, bar and tooltip key go to `te_culture_merges_generated_l_english.yml` (`organize_loc` category `CULTURE_MERGES_GENERATED`: `CULTURE_MERGE_RESULT_KEYS` and the `te_cmg_` and `je_te_cm_` prefixes); the shared phrases (`te_cm_*`) are hand-written in `te_miscellaneous_l_english.yml`. Cultures are spliced (`$north_german$`), never spelled, and every figure in the text is a script value, never a digit; tests check both. The plural demonyms are not generated (§ Compatibility).
- **Generated names** (per merge `<m>` and slot culture `<c>`): triggers `te_cmg_<m>_is_candidate`, `_can_start`, `_start_basics`, `_core_ok`, `_result_switched` (the one place that reads `te_cm_switched_<r>`, every merge), `_core_left` (British, American, Platine), `_<c>_available`, `_<c>_measured`, `_<c>_switched_in`, `_<c>_can_join`, `_<c>_years_met` (tiers 1b and 2), `_<c>_waiting`, `_census_wanted`, `_starter_gone`, `_is_starter`, `_has_other_starter`, `_core_switched`, `_all_switched`, and the culture-scope `te_cmg_is_switched_part` and `te_cmg_switched_part_kept`; effects `te_cmg_census_all`, `te_cmg_census_<m>`, `te_cmg_census_<m>_country`, `te_cmg_<m>_result_sol`, `te_cmg_<m>_settle`, `te_cmg_<m>_join_ready`, `te_cmg_start_<m>`, `te_cmg_release_lost_starters`, `te_cmg_yearly_country`, `te_cmg_dominance_all`, `te_cmg_monthly_country`, `te_cmg_copy_fervor_all`, `te_cmg_set_fervor_from_source`, `te_cmg_formed_country`, `te_cmg_remove_switched_part_homelands`, `te_cmg_remove_parts_of_<culture>` (eleven) and `te_cmg_debug_dump`; values `te_cmg_<m>_lowest_dom`, `_lowest_dom_all`, `_progress` and `_bar_pct`. The hand-written helpers are in `te_culture_merge_effects.txt` (among them `te_cm_join_part`, `te_cm_unjoin_part` and `te_cm_release_starter`) and `te_culture_merge_triggers.txt`; every number is in `te_culture_merge_values.txt`.

## Census and Gates

- **When:** `te_cm_yearly_on_action` on `on_yearly_pulse_country`. The first country whose pulse falls in a new calendar year runs the global census (`te_cm_census_year`, compared with `value = year`; the 330-day `te_cm_census_lock` is only a backstop), so every counter adds one a calendar year. In order: `te_cmg_release_lost_starters`, `te_cmg_census_all`, `te_cmg_dominance_all`.
- **What is counted:** `te_cmg_<m>_census_wanted` is an idle merge some country is a candidate for, or a running or complete merge with a living starter, its result not switched, and an unswitched slot culture still somewhere in the world. Each wanted culture is walked once (`te_cm_census_culture`, or `te_cm_census_culture_joined` for a joined part, which also sums the result); then each candidate of an idle merge, or the starter of a running or complete one, runs `te_cmg_census_<m>_country`: one `te_cm_census_part` per slot culture at its own tier, skipping a switched one.
- **Homeland states only** (owner): every share is taken over the part's pops living in the part's homeland states, whoever holds them. Diaspora pops convert at the switch but don't weigh on any gate. A culture with no owned homeland state is counted in the world instead.
- **Hold** (`te_cm_held_<m>_<c>`): the sphere's pops of the part in those states over `te_cm_home_<c>`. For a joined part both sides count part + result (R22), so conversion doesn't erode the hold: a starting hold of 0.67 would otherwise close before the switch. Opens at 0.60, closes below 0.50.
- **Acceptance**, tested only while the part hasn't joined (R29): `country_average_culture_pop_acceptance` in every sphere country holding at least `te_cm_meaningful_share` (0.10) of the sphere's homeland pops of the part, and always in the largest holder (the cut-off is capped at its holding, so a thinly split part can't pass vacuously). Accepted is vanilla's Full Acceptance, `acceptance_status_5` (80), lost below 75; for a tier-1b part, very high, 90, lost below 85. The owner's rule (R39): a country where the part holds only `acceptance_status_4` (60 to 79, which the mod's `replace/` loc calls Provisional Acceptance) treats it as second class and can't merge it. The status rows splice `$full_acceptance$` and `$second_rate_citizen$`, so they read as the pop panel does. Holders are noted in the temporary `te_cm_tmp_cnt`. The part's `te_cm_ok_<m>_<c>` is hold and acceptance with hysteresis, and for a joined part the hold alone.
- **Standard of living:** `te_cm_sol_<m>_<c>` is the part's pop-weighted standard of living over the same pops. The merge-wide `te_cm_sol_ok_<m>` covers the core parts only (R23): the gap between the best- and worst-off measured core parts opens below 3, once every core slot is met (R25), and closes above 4. The census keeps the range's two ends, their figures and the gap (`te_cm_sol_best_<m>`, `_worst_`, `_hi_`, `_lo_`, `_gap_`), so the status row can name them; they are for display only and go when no core part has a figure. Each optional part has its own `te_cm_sol_ok_<m>_<c>` (`te_cm_sol_gate_part`) over the core range plus the part. Once no core part has a figure (all switched), the reference is the result's pop-weighted standard of living in the sphere's homeland states of the core parts (`te_cmg_<m>_result_sol`, walked only while an optional part is unswitched and its `te_cm_ok_<m>_<c>` is 1, since the figure is read only then; R26, R35, R38).
- **Years together** (`te_cm_years_<m>_<c>`, tiers 1b and 2): +1 each census while the part's gate holds, never reset; `te_cm_years_tier2` 30 and `te_cm_years_tier3` 50.
- **Availability** (`te_cmg_<m>_<c>_available`): a culture is in at most one running merge (`te_cm_in_<c>`). A slot culture that is another merge M's result (`french`, `cm_italian`) is available only while M is complete with every joined part switched, or while no part has ever joined M (R33). A switched culture never joins again (R32). Anglophone's counter carry: `te_cm_census_part` adds a year whenever the gate holds, with no availability test, so `te_cm_years_anglophone_cm_american` accrues while American runs, and the slot falls on that counter, not a fresh one, when American completes (review A; it can be lower than Yankee's was).
- **`can_join`:** the part's gate, available, not joined, not switched, the merge's own result neither switched nor, for the eleven merges whose result can switch, joined to a higher merge (`te_cm_in_<r>`, R38: once Latin has joined `french`, the French merge takes no Catalans, which would stall Latin's slot until they switched), the part's own tier technology, its years (tiers 1b and 2), and for an optional part its own standard-of-living gate.
- **`can_start`** (`te_cmg_<m>_can_start`, a list of `custom_tooltip`s, so the button's reasons and the status rows read the same conditions): idle; the result not switched (the eleven merges whose result is a wider merge's part, R36); a core culture primary; the start tier's technology; each core slot met, through a measured alternative (gate on, available, not switched, years met, its own technology in a mixed core) or a joined and switched one (R21); `te_cm_sol_ok_<m>`; the components at state 2; Brazil's content check; the waits. `test_every_condition_of_is_candidate_is_in_can_start` holds `is_candidate` to a subset of `can_start`; it caught a candidate able to start Italian after `cm_italian` had gone into Latin, and Brazil's missing content check.

## Bespoke Gates

Each merge's own historical precondition (owner, 2026-11-09), beyond the gates every merge has: what had to be settled before these peoples became one. Bespoke rather than systemic on purpose, for verisimilitude; no time cap, unlike the waits (an unformed Germany keeps the split, which is the point).

- **Where:** `Gate(trigger, milestone, clause, why)` in the roster, on a `Merge` or on an optional `Part`; each trigger is hand-written, country scope, in `common/scripted_triggers/te_culture_merge_gate_triggers.txt`, with its history in a comment. `clause` and `why` are player text (names spliced, no digit). The names-not-spelled test matches any result's name as a substring, so "Germany" or "Arabic" fails it: splice `$GER$`. A spliced vanilla name reads as a proper noun ("no $je_acw_war$ under way" shows "no The American Civil War under way"), so word around it.
- **Milestone** (a formation, Meiji): `te_cmg_<m>_gate_ok` = the trigger, or the country variable `te_cm_gate_met_<m>`, which the census (`te_cmg_census_<m>_country`) and the start set while it holds, so a later formation (Germany into United Europe) or a civil war's winner keeps it. Read in `can_start` only.
- **Standing** (a law, independence): `te_cmg_<m>_gate_ok` = the trigger. Read in `can_start`, in `join_ready`'s guard and, on the starter, in the yearly conversion's whole-merge test, in both states: while it fails no culture joins and none converts, complete or not. The entry's `paused` row (after `complete`, before `late`) says so.
- **A part's gate** (optional parts only, standing only; `validate` refuses the rest): the trigger joins that culture's `can_join` and its conversion limit, read on the starter.
- **Shown:** a `can_start` line `te_cmg_<m>_gate_tt` after the technology, a status row `je_te_cm_<m>_status_gate` (the `why`) after the components and before the slots, so the formation isn't hidden behind a hold row, and a sentence in the entry's reason.

## Conversion

- **When:** every country's own yearly pulse runs `te_cmg_yearly_country`, inside the rule gate but outside the census's year guard and lock. For each running or complete merge with a living starter, a country in the starter's sphere converts when the merge is complete or the starter's `core_ok` and `te_cm_sol_ok_<m>` hold (the whole-merge stall, while running only). Then each joined, unswitched part whose starter-side `te_cm_ok_<m>_<c>` is 1, and for an optional part `te_cm_sol_ok_<m>_<c>` too, runs `te_cm_convert_part`. A stall keeps every pop already converted, and every counter.
- **The pause, per country** (R29, spec § 4.3): a converting country whose average acceptance of the part falls below 75 (85 for a tier-1b part) sets `te_cm_paused_<m>_<c>` and converts none of that part until it is back at 80 (90). It counts only where the country holds at least 0.10 of `te_cm_home_<c>` in the part's homeland states. That is the world's homeland pops, not the sphere's holding, because a converting country has no cheap read of the sphere's total; so slightly fewer countries pause. A sliver holder neither pauses nor blocks.
- **Primary culture** (R34): the result is added as a primary culture where the part being converted is primary, and always in the starter. A sliver holder converts its pops without gaining a primary. The add is guarded on every pass, so a formation that dropped it gets it back. `te_cm_converted_<m>` marks the country for the formation hook.
- **Rate** `te_cm_pop_rate` (pop scope; the caller saves `scope:te_cm_part` and `scope:te_cm_starter`): each pop of the part runs `change_pop_culture` with this fraction.
  - rate = `te_cm_base_rate` (0.012) × (`te_cm_literacy_base` 1.5 + the pop's `literacy_rate`) × (1 + `te_cm_urban_weight` 0.6 × `state.state_urbanization_rate`) × (1 + the owner's `country_culture_merge_speed_mult`), clamped to 0–0.5;
  - × `te_cm_discriminated_factor` (0.1) when `pop_acceptance < acceptance_status_4`: per pop and exact, a cliff at 60, Open Prejudice or worse, kept there though the country gate opens at 80 (R39): the gate reads a country's average, the factor each pop, so a pop at 57 converts at a tenth while its country's average keeps the merge running;
  - × `te_cm_diaspora_factor` (2) when the pop's state region is not a homeland of the part;
  - × `te_cm_sphere_rate_factor` (0.5) when the owner is not the starter.
- **Pace**, pinned by `test_culture_merge_values.py`: a part switches after n = ln(1 − 0.60) / ln(1 − f) years, for a starter that holds the part's whole homeland. Only the sphere converts, and for a new culture the result's pops in a homeland come only from that conversion, so dominance can't pass the sphere's hold h. The switch share equals the hold that opens a merge (60%; owner, 2026-11-07, after review B's I2 showed a 2/3 switch left a sphere at 60–66% unable to finish): a sphere at exactly 60% can finish only by gaining more of the homeland, and at h the switch takes ln(1 − 0.60/h) / ln(1 − f) years, about 28 at h = 0.8 and 40 at h = 0.7 on the developed profile (absorb merges, another part's diaspora switch and migration aside). Gaining more of the homeland is the player's lever. A developed profile (literacy 0.8, urbanization 0.4, Public Schools + Ministry of Culture level 3 + Radio + Film, speed +40%) gives f 4.8% and 18.7 years; a slow one (literacy 0.3, urbanization 0.1, no sources) 2.3% and 39.6 years; a bloc member on the developed profile 2.02× as long. Between the two profiles literacy alone moves the rate ×1.28, urbanization ×1.17 and policy ×1.40, about half circumstances and half policy, as the owner asked (R15). A maxed country takes about 12 years; a discriminated pop effectively never converts (about 190 years); a diaspora pop on the developed profile about 9 years.
- **Pop count.** A fractional conversion splits a pop, so a running merge carries extra pops until the switch. Whether the next pass merges the converted share into the result's existing pop is the self-check `cm_conversion_merges_pops`; the fallback is fewer, larger steps.

## The Switch

- **Dominance** `te_cm_dom_<m>_<c>` (`te_cm_census_dominance`, from the census's globals, no second walk): `te_cm_home_r_<c>` / (`te_cm_home_<c>` + `te_cm_home_r_<c>`), both read guarded. A zero denominator gives 1 (a part gone from the world, or whose homeland holds neither culture, R35), so its diaspora still converts. `te_cmg_dominance_all` runs it, after the census, for every running or complete merge with a living starter whose result hasn't switched.
- **At `te_cm_switch_share` (0.60)**, `te_cm_switch_part`: (1) every pop of the part in every country converts whole (`value = 1`); (2) every homeland state of the part gains the result's homeland where it lacks one (`add_homeland` adds beside the part's: self-check `cm_switch_homeland`); (3) `te_cm_switched_<c>` = the result, `te_cm_in_<c>` removed; (4) the merge goes to state 2 once `te_cmg_<m>_core_switched` (every joined core part switched, and at least one); (5) a human starter gets the popup `te_culture_merge.1` (`events/te_culture_merge_events.txt`), "From <part> to <result>", the two cultures saved as `scope:te_cm_ev_part` and `scope:te_cm_ev_result` (permanent saves, so each popup keeps its own pair when two parts switch in one census; nothing told the player before, 2026-11-09). A late part switches the same way, on its own homeland states.
- **Homelands kept** (owner, 2026-11-07): `te_homeland_removal_candidate` (`homeland_triggers.txt`) ends in `NOT = { te_cmg_switched_part_kept = yes }`, so Dynamic Homeland Progress leaves a switched part's homeland alone while the state is also a homeland of the culture it switched into. When it removes that culture's homeland, `te_cmg_remove_switched_part_homelands` (called in the same `state_region` block of `te_homeland_removal_monthly_effect`) removes the parts' too, following a chain through `te_cmg_remove_parts_of_<culture>`: removing `cm_latin` takes `cm_italian`'s homeland and Corsican's in the same step. A removal project begun for a part before it switched is dropped. The parts' homelands are kept because a formable with `use_culture_states = yes` counts states by the homelands of the cultures its country definition lists (the parts, which no effect can edit), and every `is_homeland = cu:<part>` read stays true.
- **Monthly upkeep** (`te_cmg_monthly_country` → `te_cm_monthly_switched_culture` per switched part, `on_monthly_pulse_country`): a country with a switched part as a primary culture gets the culture the part's people are in now (Austria at the switch, a country formed or released later from a definition that lists only the parts), pops of the part that reappear convert whole (vanilla's `philippines.11` converts Mestizo pops into Filipino, a part of Pan-Malay), and the part leaves the primary cultures once nothing is tied to it (§ Leaving the Primary Cultures). "The culture its people are in now" is the end of the chain: `te_cmg_resolve_switched_result` follows `te_cm_switched_<c>` from North Italian through `cm_italian` to `cm_latin`, lowest result first, so a removed `cm_italian` is not added back each month. `on_country_formed` runs it at once (`te_cmg_formed_country`, which also gives the result back to a starter, or to a converting country where a joined part is primary).
- **Completion** (R5): the complete outcome needs state 2 and `te_cmg_<m>_all_switched`. While a late part still converts, the entry shows its late row, with the lowest dominance over every joined, unswitched part.
- **Chains** (R33): a higher merge takes a lower merge's result only once the lower merge is complete with every joined part switched, or before any part has joined it. Once the higher merge has joined the result (`te_cm_in_<r>`), the lower merge takes no new parts (R38). Once a merge's result has switched (`te_cm_switched_<r>`), that merge joins, converts, measures and switches nothing more, and `is_candidate` fails: Corsican, if it never joined the Italian merge, stays Corsican once `cm_italian` has gone into Latin. R33 chose this over retargeting the lower merge onto the higher result. Before it, a complete French merge kept converting Catalans into a `french` that Latin had switched away, and they never switched.

## Leaving the Primary Cultures

Owner, 2026-11-09, in place of spec § 7's "the parts remain primary cultures forever": a part that has switched has no people left, and it is removed from a country's primary cultures once nothing is tied to it. A primary culture's traits count for acceptance whether or not it has pops, so a dead part also kept granting acceptance through traits nobody carried.

- **The removal** is the last step of `te_cm_monthly_switched_culture` (monthly and on formation, behind the rule): where the country has the part and its successor as primary cultures and `te_cmg_part_held_<c>` fails, the country's characters of the part take the successor's culture (`change_character_culture`) and `remove_primary_culture` takes the part. The successor must be primary, so a country never loses its last primary culture, and a country with no state is skipped (the on-action's guard). A formation or release that brings the part back (its definition still lists it) loses it again on the next pass.
- **The inventory** `scripts/generators/culture_merge_primary_reads.json` (`culture_merge_primary_reads.py --write`, on the machine with the game; `--check`): every vanilla entity that tests a part as a primary culture, by a brace-aware scan of `common/` and `events/` (`country_has_primary_culture = cu:x`, a `cu:x` inside an `any_/every_/random_/ordered_primary_culture` block, `cu:x = { is_primary_culture_of … }`; not a read through a saved scope, of which vanilla has two, both on cultures other rows already hold), each with the field it sits in and the journal entries that reach it through vanilla's script (`trace_entries`); every vanilla formable whose definition lists a part, with its whole `cultures` list and whether the tag owns a state in 1836; and the culture list of each trigger the mod restates; and the text of every government type that tests a part. Stamped with the game version: `test_culture_merge_primary_reads.py` fails when `vanilla_parsed/` moves to another version, and compares the file with a fresh scan where the game is installed. `99_ru_custom_loc_V3.txt` (2,100 Russian-grammar tests) is left out.
- **The ledger** `scripts/generators/culture_merge_primary_ledger.py` gives every row a disposition, and the test fails on a row with none. `python3 scripts/generators/culture_merge_primary_ledger.py` prints each part's holds and each case's parts.

- **The cases** (owner, 2026-11-09: "if other stuff would need holds, let me know and we can decide case by case"). Held until 1936: historical characters (176 templates: Spain, Portugal, Peru, Chile, Mark Twain), decisions (Austria's Trialism, deposing a ruling dynasty), laws and amendments (the American Second Amendment and Fugitive Slave Act, Serfdom and Manorialism rules for Romanian and Polish countries), and the Siberian exile pool. Not held: AI strategy and research weights; political movements, ideologies and lobbies; and single flavor events outside any journal entry (the historical agitators, the Emu War, Sweden's Bernadotte events, the Polish rebellion). On the last the owner first ruled "hold", then, shown that North German was held for one agitator event and one other read: "Holding for just these two means the hold is way too strict"; the rest of that list is filed by the same reasoning *(the designer's reading)*. Each read outside a journal entry is now classified by name, and several turned out not to be standalone at all: the Risorgimento's secession events and the German Confederation's member list belong to their entries, and a small German state asking to join a unifier is moot once Germany exists. Filed with the last, as the same kind of read *(the designer's filing, after review)*: six parties' `join_weight` terms, an interest group's pop attraction and membership effects, and the Carlist swap when Corporatism is researched. In the folders where one entity holds reads of different kinds (interest groups, parties, technologies) the ledger goes by the field the read sits in (`blocks` in the inventory, `_by_field`). A new kind of read gets a new case and waits for a ruling (an unruled case holds).
- **1936** (`WINDOW_END`). The owner said of the cases: "none should hold past 1936 - vanilla's end date". The same date ends an unformed tag's hold, which is the designer's call *(not the owner's words)*: it makes the rule one sentence. So after 1936 only a **running** journal entry holds a part, because that entry could not finish without it.
- **Any country, not this one.** An entry holds the part in every country while any country has it: an entry also tests its targets' and its overlord's cultures, and the scan can't tell whose culture a line reads. So a part can stay in Austria because Bavaria's entry runs.
- **`te_cmg_part_held_<c>`** (generated, one per culture that can switch; `always = no` for the 60 nothing holds): `OR` of the window clause (`game_date < 1936.1.1` alone where a case holds; otherwise with the unformed tags and, for an entry in `ON_OFFER_HOLDS`, `any_country = { has_inactive_journal_entry … }`) and `any_country = { has_journal_entry … }`. **Two of North and South German's eight entries have no timeout** and run in every German country from the first day: German National Identity (until North German fervor is 40 and South German 30, which the fervor copy turns into German fervor after a switch) and the Schleswig-Holstein Question (until some country settles it). Either left running keeps both cultures primary everywhere; the play-test list has the check.
- **Formables: the merged cultures join the definition lists** (owner, 2026-11-09). Forming a tag needs a primary culture from its definition's `cultures` list, and the lists name the parts: a Germany that is only German could not form the Holy Roman Empire, the European Union or UNE. `common/country_definitions/zz_te_culture_merge_definitions.txt` (generated) INJECTs 39 vanilla formables that own no state in 1836, each block restating vanilla's whole list with the merged cultures added, so it is right whether the engine appends an injected list or replaces vanilla's with it (unread: self-check `cm_definition_inject`). The mod's ten formables list them in `te_formable_countries.txt`, by hand (`gen.mod_definition_gaps` says what is missing). Every **new** culture a listed part can become is added, up the whole chain (North Italian: `cm_italian` and `cm_latin`). An absorb merge's result is never added: it is a vanilla culture with people (Dutch, for Flemish), and the tag would hand it to whoever forms it; where vanilla's list lacks it, the part is held while the tag is unformed. A start tag (CLM, FRA, GBR, POL, PRU, RUS, SPA, SWE, USA) is not injected, since its country would begin the game with an empty culture. It holds nothing either: the first build held the part while the tag was dead, and the owner's point about Prussia ended that (the German merge follows Germany's formation, and Germany, an empire, cannot form a kingdom). So a country that has only the merged culture cannot re-form a dead start tag.
- **Forming adds every listed culture**, so a country that forms the European Union gains `cm_latin` whether or not it has any claim to it. `te_cmg_strip_untouched_results` (`te_cm_strip_on_action`: monthly and on formation, **no rule gate**, since the definitions are injected whatever the rule says) takes a merged culture off a country again, unless it is the country's only primary culture, in two cases. (1) Its merge never began (`te_cmg_<m>_untouched`: idle, and no part ever joined; a merge returned to idle keeps its joined parts). (2) The merge did begin, but the country is not its starter (`te_cm_started_<m>`), has never converted for it (`te_cm_converted_<m>`), has no pops of the culture, and has none of the switched cultures that end in it as a primary culture (`gen.cultures_below`). That is Romania formed while France runs the Latin merge and Romanian has not joined, which the first build left with `cm_latin` for good (review, 2026-11-09). The last test is the monthly upkeep's own reason to give the culture, so the two can't undo each other; once that part has left, a merged culture with no people in the country goes too.
- **Consequences to know.** (1) A formable with `use_culture_states = yes` counts the homelands of every culture its definition lists, the merged ones now too: after a Latin merge, vanilla's Iberia asks for 90% of every Latin homeland, and the mod's Zhonghua (through Uighur) for Pan-Turkic homelands. Thirteen vanilla tags and Zhonghua are of that kind; the mod's others use regions or state lists. (2) The culture requirement widens with the merge: any Latin country passes Romania's, any Anglophone one Canada's. The states requirement is unchanged. (3) A game begun before the merged cultures existed has no object for them, and forming an injected tag there adds one (the rule's `exists` guard can't reach a definition).
- **Traditions carry over** (owner: "give the result the component culture's traditions where it makes sense"). `te_cmg_carry_traditions` (global monthly pulse, no rule gate, guarded so each is added once): a merged culture takes the traditions of the **core** parts that have switched into it, and a result that is itself a part passes on what it took (East Slavic's Russosphere into Pan-Slavic). Not an optional part's (Alemannic's Helvetic says nothing about Germans), nor the pairs in `culture_merges_config.TRADITIONS_NOT_CARRIED` (Ryukyuan's Sinosphere into Japanese). Twelve adds in all (`gen.carried_traditions`). Heritage and language can't be carried, a culture has one of each: 59 of 129 part slots differ from their result in one of the three, and a third culture that shared only a heritage or language with a removed part loses that acceptance term.
- **The restated trigger.** `common/scripted_triggers/00_a_te_culture_merge_vanilla_triggers.txt` (generated) is a bare copy of vanilla's `has_indian_primary_culture` with `cm_dravidian` added (owner: a small helper is worth overriding, a whole journal entry is not). It sorts before vanilla's `00_scripted_triggers.txt`, and the first bare definition of a scripted trigger wins; the engine logs one `Duplicated key` line naming vanilla's copy. A trigger qualifies for `ledger.TRIGGER_OVERRIDES` only if it is one `OR` of `country_has_primary_culture` lines: the scan raises on any other shape, so a vanilla patch that adds a condition can't be lost in the copy.
- **Ruler titles** (owner, 2026-11-09). `common/government_types/zz_te_culture_merge_government_types.txt` (generated) REPLACEs eleven vanilla government types with vanilla's own text plus the merged culture in the culture test: `gov_kaiser`, its regency and three social-monarchy forms, `gov_volksgemeinschaft` and `gov_fascist_corporate_state` (which excludes a German ethnostate) for `cm_german`, and the four American parliamentary and theocratic forms for `cm_american`. The rule (`ledger.restated_government_types`): a type is restated only where it names **every core culture** of the merge, so the title already belonged to the whole merged people; and only for that merge's own culture, never one further up the chain. The French republics and monarchies (French alone of Latin's core cultures), the Swahili sultanates and Folkhemmet are left to vanilla: restated, a Latin Spain would be a French Third Republic. A REPLACE and not a sibling type, because the engine takes the first type whose `possible` holds and vanilla lists the dual monarchy, the Danubian federation and the crown lands before `gov_kaiser`: a copy in its own file would sort ahead of them and take a German Austria's. `restate_with_result` refuses a culture test that isn't a plain `OR` naming the whole core. Another mod's INJECT into one of the eleven is lost.
- **Interest-group names need nothing.** Vanilla sets them once, in each group's `on_enable` (`set_interest_group_name`, in four groups), and a name stays set: the Russian Orthodox Church keeps its name when Russian leaves. A country created later starts with the cultures its definition lists, the parts among them, so its `on_enable` sees them before the next monthly pass takes them off.
- **The mod's own companies keyed on a part** name what it merges into (owner, 2026-11-09): Sibur (Russian, East Slavic, Pan-Slavic), Shell Pernis (Dutch, British, Anglophone), IG Farben Buna Werke (North German, German). Vanilla's twelve culture-gated companies still close to a country that has lost the part.
- **Not mirrored:** party names (an injected `name` replaces vanilla's whole ladder, so eleven parties would be restated), flags, country and bloc names, train and clothing graphics, and the government types above that name one nation only. A country that has lost its parts shows the general ones (#1564).
- **Self-checks:** `cm_dead_primary_removed`, `cm_untouched_stripped`, `cm_tradition_carried`, `cm_definition_inject` (play-test list).

## Compatibility

- **Rule:** see § Culture Merges System (R19, R20, R27).
- **Country-level reads of a part** (`country_has_primary_culture = cu:<part>`, `any_primary_culture`, a formable's definition list; 1,727 reads in 591 vanilla entities, 1.15) are live while the part is a primary culture, and a switched part stays one while any of them still matters: § Leaving the Primary Cultures. `is_homeland = cu:<part>` reads stay true for good, since the parts' homelands are kept.
- **Fervor copy** (owner, 2026-11-07, R41, in place of R37's waits on `je_german_unification_idea` and `je_the_balkan_league`). A switched culture has no pops, so its target fervor is 0 and its current fervor drifts toward it (`CULTURAL_FERVOR_DRIFT`, about 1% of the gap a month). Vanilla reads parts' fervor in German National Identity's completion (North German at least 40, South German 30), the Balkan League's `possible` (Serb, Bulgarian or Greek above 75), the Balkan national awakenings, the German, Italian and Yugoslav pan-national movements' `creation_trigger` (above 10), `movement_values.txt`'s averages and the Tsar points button on Russian fervor. Once a month (the global `on_monthly_pulse`, `te_cm_fervor_on_action`, no rule gate) `te_cmg_copy_fervor_all` sets every switched culture's fervor to the fervor of the culture it switched into (`te_cm_copy_fervor`), a result before its own parts (`fervor_copy_order`) so a chain settles in one pass; at the switch, before any pop converts, the result takes the part's fervor where its own is lower (`te_cm_switch_part`), so the copy doesn't drop it. Every set goes through `te_cmg_set_fervor_from_source`, a generated ladder of literals that rounds down to the half point (`fervor_ladder`): `set_fervor` is documented with a literal only, and an effect that read a named value as 0 would zero the culture (review of 65cdfce). Rounding down, a copy never passes a threshold its source hasn't. **Not Ukrainian or Byelorussian** (`culture_merges_config.NO_FERVOR_COPY`): vanilla reads their fervor only for an identity apart from Russian, their Cultural Renaissances (opening at fervor 15 and 20) and the Russian Civil War's releases (fervor 10, `05_russian_civil_war_triggers.txt`), so copied from East Slavic it would reopen a renaissance for a culture with no people; theirs drifts to 0 and that content stays shut, as before the copy. An INJECT couldn't do this for the Balkan League: its test sits in `possible`, and an INJECT that adds a second `possible` is rejected (`scripting_best_practices.md`, the INJECT order probes). Self-check `cm_fervor_copy` (that the copy holds a month on a culture with no pops). A merged-away culture shows a fervor in its panel though it has no people. The renaissances' waits cover an entry already active.
- **Russification** (`je_russification`, in game "The Western Border") gets an injected second success outcome instead of a wait (`common/journal_entries/te_vanilla_russification_merge.txt`): vanilla's copied field for field, with the state test widened from Russian to Russian plus East Slavic (`te_cm_russification_complete`, `te_cm_russification_state_ok`, `te_cm_russian_or_east_slavic_share`). No rule gate: converted pops stay East Slavic whether the rule is on or off. Unverified in game (self-check `cm_russification_outcome`; fallback: `je_russification` in East Slavic's `wait_for`). The panel lists two success rows with the same headers, the map highlight (`je_russification_state_is_russian_assimilated`) still counts Russians only, and a vanilla patch to the outcome must be mirrored (`test_culture_merge_russification.py` compares the copy with the snapshot).
- **Brazil:** the merge is skipped under `rp1_content`, whose nation building (`02_brazilian_nation_building.txt`, `culture_brazil_events.txt`) converts into Brazilian itself.
- **`je_vernacular_policy`** assimilates Catalan, Occitan and Walloon into Spanish and French, the direction the French merge takes, so the two agree; no wait.
- **The mod's own content keyed on a part** must name the part's successors too, in the same `OR` or list, or carry `# REVIEWED YYYY-MM-DD (culture_merge_ref): reason` (`test_culture_merge_mod_refs.py`, over every `.txt` in `common/` and `events/`). Ten references gained the result (IG Farben Buna Werke, the Majapahit, Ottoman and Rashidun names, five party names, the FPTP seed); 15 decline it, mostly `cm_latin`, `cm_anglophone` and the pan-merges on national party-name ladders, where the result would hand one nation's name to the others (the two companies that declined it name it since 2026-11-09). A declined name goes dark once the part has left the country's primary cultures; names are cosmetic, which holds nothing (owner, 2026-11-09). Generated vanilla restatements (`common/ideologies/modified.txt`, `zz_te_party_join_weights.txt`, `extra_law_consistency_generated.txt`) are exempt and pinned.
- **What goes dark after a switch.** Not patched: a merge never overrides vanilla content (spec § 7).
  - Fervor: no longer dark; the fervor copy above keeps every read of a switched part's fervor on the merged culture's.
  - Pop tests: `balkan_wars.9` (`has_pop_culture = turkish`), `tsarpoints_events.9` (Byelorussian, Ukrainian), the Civil War's Wild West robbery (Dixie, Yankee).
  - Shrinking shares (`culture_percent_state` / `_country` on a part): Russification's decrees and assimilated-state trigger, the Algerian departments (French), Goa (Portuguese), the Ukrainian plurality trigger of the Russian civil war.
  - Characters are not converted: a historical character keeps the part's culture, and one generated later for a `cm_` country takes the result. Clothing and headgear keyed on `culture = cu:<part>` (105 lines in `gfx/portraits/portrait_modifiers/`) match no `cm_` culture, whose portraits fall back to the first core part's graphics set; ship names keyed on a part (12 lists) fall back to the default list for a country whose only primary is the result.
  - Demonym plurals: the four demonym ladders (`demonyms_custom_loc.txt`) list no `cm_` culture and end on an unconditional default that prints the culture's name, so a `cm_` plural reads as its singular ("German" for "Germans"). `customizable_localization` takes no INJECT, and an injected entry would sit behind the default anyway (`scripting_best_practices.md`). A follow-up, unbuilt, is a `localization/english/replace/` override of `PLURAL_DEMONYM_DEFAULT` that calls a mod-owned culture-typed custom loc; only mod cultures reach the default. Russian locale's `RU_CUL_ADJ` has no entry for a `cm_` culture either.
- **The 21 `cm_` cultures exist from 1836 with no pops.** 24 mod files iterate cultures (`every_culture`, `any_primary_culture` and the like); whether any divides by, averages over or lists them is on the play-test list.
- **Known limitations:** a complete merge whose starter is conquered (not a civil war) takes no late joiners, and lets go of the parts it was still converting (R38); a merge whose waits are all on optional parts never reaches the wait cap; the pause's meaningful share is measured against world homeland pops; the census and conversion cost is unprofiled (play-test list § Cost).
