**`banking_system_rule` has three settings.** `banking_system_enabled`, `banking_system_simplified`
and `banking_system_disabled`. The middle one keeps the Banking Cycle journal entry — the cycle,
its crashes, the prudential and command/cooperative tools, the financial-regulation laws — and
switches off the monetary-policy layer built on top of it (`monetary_policy_design.md`
phases 1–5): no policy-rate dial, no inflation, no exchange rate, no pegs / swap lines /
guarantees / shared currency. Two scripted triggers tell the halves apart, and **nothing reads
the rule directly any more**:

| Trigger | File | True for | Asked by |
|---|---|---|---|
| `te_banking_system_on` | `common/scripted_triggers/banking_policy_triggers.txt` | enabled **and** simplified | the journal entry's `is_shown_when_inactive`, the banking history series |
| `te_mon_full_system` | `common/scripted_triggers/te_monetary_triggers.txt` | enabled only | every step of the monetary layer (see § Banking Cycle → Monetary Policy) |

Both read only a game rule, so they work from any scope — country, journal entry, treaty
article, power-bloc principle, GUI.

**Early and late unlock** (2026-11-13, Steam Workshop feedback). A rule whose system opens at an era 6 or 7
technology can have a third setting that opens it at an earlier, historically fitting one, with the parts that only
make sense later kept behind their own technology. The late setting is the system as it was and keeps its old
setting name and flag (`<system>_enabled`), so a save made before keeps it; the new setting is
`<system>_early_unlock`. Every setting has one flag, named after it: whether `has_game_rule` reads a second flag on a
setting is unverified (vanilla's own reads name a setting, `allow_monument_effects`, whose flags are all
`disable_pm_*`), so no setting borrows another's name. Script reads these rules only through two triggers per
system in `common/scripted_triggers/te_rule_setting_triggers.txt`, `te_<system>_on` (either unlock) and
`te_<system>_early`; `test_rule_unlock_settings.py` fails on a bare `has_game_rule = <system>_enabled` anywhere else,
which would now mean the late setting alone. The early settings are new and not play-tested
(`docs/testing/early-unlock-rules-playtest.md`); each default stays as it was.

**Gating pattern:** Each rule sets a flag checked via `has_game_rule = <flag>`:
- **Journal entries:** `is_shown_when_inactive = { has_game_rule = X_enabled }`, `disable_evaluation = { NOT = { has_game_rule = X_enabled } }`, and an invalid outcome on the rule off (below)
- **On-actions:** Early `return = yes` if `NOT = { has_game_rule = X_enabled }`
- **Diplomatic actions:** `potential = { has_game_rule = X_enabled ... }`
- **Trait assignment (aptitude):** `limit = { te_aptitude_traits_enabled = yes  OR = { has_game_rule = universal_aptitude_traits_enabled  has_role_of_type = ruler  has_role_of_type = heir } }`

**Switched off mid-game** (2026-11-08). `disable_evaluation` prunes only inactive records, so every rule-pruned entry also ends on its rule, through its one hidden invalid outcome (the rule folded in with `OR` where it had one) or, for the Nuclear Program, by deactivating; each system clears what it left outside the entry. Inventory and in-game checks: `docs/testing/rules-off-midgame-playtest.md`; the rule: `scripting_best_practices.md`, the `disable_evaluation` bullet.

**Back when switched on: the nets** (2026-11-15). `disable_evaluation` removes every other country's inactive record while the rule is off, from the game's start when it began off, and a concluded entry leaves none, so a rule switched on again finds no record anywhere. An entry returns only where a monthly pass adds it to a country with no record. Covert Warfare's and Cultural Hegemony's nets read the entry's own "would end now" trigger (`covert_warfare_entry_would_end`, `ch_entry_would_end`, the invalid outcome's whole trigger), so the net's condition and the outcome's can't drift apart; a loop from a rule read that differs between the outcome and the on_action is caught by the self-check and held. Each adds only once a country has been due for a whole month (`iw_entry_net_waiting`, `ch_entry_net_waiting`, as `ce_reentry_monthly` waits), which keeps it off a concluded record the engine may still hold for a few days and off a country formed that month, at the cost of up to two months' delay. Each has a self-check (`covert_entry_return`, `ch_entry_return`) that reads the add a month later: a first BROKEN marks the country for 400 days (`_strike`), and a second while the mark stands holds the net off it for a year (`_hold`), so a rule read that differs makes the entry come back twice in sixteen months, and a player's quick double switch costs no more than two months. Not built: World War (an entry ended on the rule doesn't come back, as before) and the United Nations, whose organisation ends with the rule (`un_stop_for_rule`) and which a founding conference then can't found again for members to join. World War's return was tried and taken out (review of #1823): the outcome's teardown and the monthly sweep clear every power's phase variables, so an off-and-on during or after a world war would bring the entry back at the leadup with no `ww_active_phase` or `ww_peace_concluded` anywhere for `world_war_conditions_met` or the net to read, and two opposed observer powers could start a second world war under Late Unlock. Treating a power past the leadup as having fought its war doesn't fit either: `ww_mark_entry_resolved` reads the early setting, which is false while the rule is off, so it would mark an early war as the last one, and a check across every country would depend on the order the outcomes fire in, since each clears its own power's variables. A game begun with World War off and switched on mid-game gets no entry at all: a net would have to restate the entry's `possible` (an opposed great power), which `add_journal_entry` skips. Both are #1826.

**A base-game rule the mod cuts down: Base Construction Capacity** (`free_construction`, #1768). Vanilla's rule (`game/common/game_rules/00_game_rules.txt`) has three settings: Scaled (All), with no flag; Scaled (Player Exemption), the default, flagged `free_construction_scaled_player_exemption`; and Maximum, flagged `free_construction_unscaled`. None has an `apply_modifier`. The engine reads the two flags to scale `country_gdp_construction` (+10 construction) to GDP, and the mod empties that modifier, so no setting changes a country's construction (`construction.md` § Free Market Construction off). Base Construction comes from `free_market_construction_rule` instead.
- **The copy.** `common/game_rules/00_a_te_free_construction.txt` redefines the rule with that one setting, keeping the default's name and flag. `replace/` loc renames the setting No Effect and says where Base Construction comes from. `common/game_rules` takes no `REPLACE:` (it isn't on the Modding-Digests 1.12.0 `inject_types.md` list), so the copy is bare. Its file name sorts before vanilla's `00_game_rules.txt` because the engine keeps a key's first bare definition in every folder probed (`scripting_best_practices.md` § Load Order, facts 1-3). `game_rules` does the same (read 2026-11-13): the launch logs `Duplicated key free_construction will not be created from file: common/game_rules/00_game_rules.txt:42` once, registered in `docs/audits/mod_known_noise.md`, and a log line naming the mod's file instead would mean the copy lost.
- **The engine can't hide a rule.** A rule takes only `default` (static or conditional) and settings carrying `flag` / `apply_modifier` (1.15 data types: `GameRule` offers `GetName` and `GetSettings`). The Game Rules screen (`gui/game_rules.gui`) lists every rule in a `fixedgridbox`, so hiding one means overriding that whole vanilla file. That was judged not worth its compatibility cost.
- **Old saves.** A save made under the default keeps its setting. A save made under Scaled (All) or Maximum names a setting no file defines any more, which the engine drops at load (`debug.log`: "Failed to read key reference"). What its Game Rules screen shows then is unread. What `has_game_rule` reads for a rule a save doesn't list has one reading: the default (2026-11-27, the 2050 game, begun before `te_batch_investment_rule` existed and loaded with the rule in a variant mod: `has_game_rule = te_batch_investment_enabled`, the default, read yes and `_disabled` no; the owner's last lobby did not list the rule either, so this does not tell the default from the last lobby's setting). The one reading points to the default: a campaign begun before `te_small_economy_construction_rule` existed and played on after it was added wrote `te_small_economy_construction_disabled`, its default, into its 1947 save (`scripting_best_practices.md` § "A Save Names Each Game Rule's Setting, Not Its Position"). That is what the save wrote, not what the trigger read before it, and the setting could as well have been the last lobby's, as `apply_modifier`'s is (§ "A Game Rule's `apply_modifier` Does Not Follow the Save"). So the table's "a save from before the rule" means one that holds no setting for it, if the engine leaves one. Only three rows depend on it, the three whose default is on and whose check is positive: `demographics_rule` and `global_commons_rule` run their default instead if the save takes it, and `culture_merges_rule` (on by default from 1.4.0) would start the eleven merges into a culture that already exists. `assimilation_cultures_rule` does not depend on it: its default, Unrestricted, is also the branch a save with no setting takes. To settle it, load a save from before a rule with the harness (`game_qa`) and read `has_game_rule` for each of the rule's settings.
- **What could still differ.** Vanilla's AI construction target (`ai_strategy_default`'s `wanted_construction_output`) reads `has_game_rule = free_construction_unscaled`, and Player Exemption for a human country. A `has_game_rule` naming a setting no file defines passes (read 2026-11-13: `scripting_best_practices.md` § "`has_game_rule` on a Setting No File Defines Is True").
