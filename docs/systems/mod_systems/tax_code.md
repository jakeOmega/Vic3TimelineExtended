# Legislated Tax Code

Part of the [mod systems reference](../mod_systems.md), which indexes every system.

## Legislated Tax Code (`je_tax_code`, `te_tax_code_rule`)

**Experimental, default off.** Under the rule the five vanilla taxation laws cannot be enacted; every country holds the carrier `law_te_tax_code`, whose generated amendments set each rate, and taxes change only through a bill that interest groups must commit to, taking effect on the 1st of its month. The customs option legislates a market owner's tariffs too. AI countries legislate through the same commands (package 6, the schema's "AI legislation"): a staggered monthly step raises taxes on a fiscal-deficit streak, cuts them on a surplus streak, passes emergency bills, bargains with the same offers and keeps or renegotiates its promises; their tariffs stay native until the customs probe (P09b/P09c) decides the mechanism. The UI is the journal entry and the Budget panel's Tax Code tab, and another country's National Info shows a read-only copy: its enacted code, passed bills, the bill it is debating and its history.

**Switched off mid-game** (2026-11-08). A game rule can be changed mid-game, from the screen that changes country, and `disable_evaluation` touches only inactive records, so the entry, and under the light code its relief and reactions, ran on after its rule was switched off. It now ends through a hidden invalid outcome on `NOT = { te_tax_code_on = yes }`, taking the light code's 22 declared modifiers along, and `te_tax_rule_off_net` (monthly, a country that holds the carrier or a migration marker) runs `te_tax_leave_code_for_rule`: the carrier gives way to the vanilla taxation law the enacted code is equivalent to (the order of `te_tax_code_equivalent_*`, restated without the rule; `test_rule_off_teardown.py` holds the two together), its amendments going with it; `te_tax_migrated` and `te_tax_light_on` go to 0; `te_tax_clear_ig_views_for_rule` clears the view bands (every band reads 0 with the rule off, so the generated swap removes each); and `te_tax_clear_relief_for_rule` takes the relief modifiers off. That replacement sidesteps an unprobed question, whether an amendment whose `possible` has turned false stays on the carrier (if not, the carrier's own rates are 0). Switched back on, the dispatch's self-heal migrates the country again from its vanilla law. Switching between the enabled settings mid-game is not handled. Play-test: `docs/testing/rules-off-midgame-playtest.md`. **The entry's safety net covers the full code too (2026-11-13).** The Tax Code tab opens only while the entry is active (`te_budget_tax_tab_sgui`), and under the full code that tab is the only place a tax is changed. `disable_evaluation` prunes the inactive record while the rule is off, so a country whose rule was switched on during play has the code in force (the monthly dispatch migrates it) and no record for the engine to activate; Banking's net showed the engine can leave a country without a record in an ordinary game as well. A Workshop player reported the tab greyed for ten years under the full code, its tooltip saying the conditions were met: the code was in force and the entry was not active. Only the light setting had a net. `te_tax_full_entry_net`, on each country's monthly pulse, now adds the entry to a country with the full code in force and no record of it, active or inactive (`test_tax_code_scaling_modifiers.py`). **What that does not cover:** the greyed tab's tooltip reads only `has_journal_entry`, so it is the same for a country with no record and for one holding an inactive copy the engine never activates, and `add_journal_entry` is refused while an inactive copy exists. Which state the player was in is not known, nor whether the second occurs at all. Beside each net a handler (`te_tax_light_entry_stuck`, `te_tax_full_entry_stuck`) therefore runs `te_tax_entry_stuck_check` (`te_tax_migration_effects.txt`), which writes `TE_SELF_CHECK BROKEN tax_entry_inactive_stuck` for a country that has had the code in force, the entry not active and an inactive copy for three months running.

The fourth setting, *Light Tax Code* (`te_tax_code_light`, gated by `te_tax_code_light_on`), keeps the vanilla taxation laws: each law caps every tax it levies at its very-high rate and every levied tax may be cut to nothing, and the player moves each rate a step at a time from the tab, with no bills: the rate and the tax level move at once, the relief and the reactions within days. The native tax level is the highest step any tax sits on (the tax-level buttons are greyed) and every tax below it carries a relief static modifier, so the country collects the code's rates; the taxed goods and tariffs stay native. The relief and reaction modifiers (21) are `scaling_modifiers_while_active` declarations on `je_tax_code` since 1.15 (#1404), and the low dividend tax's levy (below, 2026-11-15) is a 22nd; each is a generated value that reads the country's variables (`te_tax_light_rl_<key>`, `te_tax_en_div`, `te_tax_lr_mag_<ig>` by the sign of `te_tax_lr_<ig>`), so under the light setting the entry carries gameplay, not only display; a monthly net, `te_tax_light_entry_net`, adds it to a country in force the engine left without one. The view bands stay flat country modifiers, which the full code shares. Interest groups react to each change (the support model's material and ideology reasons for the step; a pleasing reaction counts half; ±10, fading 30% a month) and the view bands reward relief instead of judging a resembled law, since the engine already gives the enacted law's stance. AI countries keep choosing their tax level and their code follows it. At an outbreak the rebels receive the original's light code and keep it while the war lasts, their taxes moving with the level their AI sets, so a rebel winner continues the nation's rates (#1469). Schema and sync: [`tax_code_schema.md`](../tax_code_schema.md), "Light code"; design: `docs/superpowers/archive/specs/2026-10-09-tax-code-light-design.md`.

**The low dividend tax** (owner, 2026-11-15: "allow dividend taxes in the tax code on any law, at a low level, in light mode"). Under the light setting a law that levies no dividend tax (Consumption-Based, Land-Based, Per-Capita) lets the code levy one from nothing up to 5% (`LIGHT_EXTRA_CAP_DIV` = 2 index steps in `gen_tax_code.py`'s `LIGHT_EXTRAS`: Proportional's Low rate, half its Medium and a quarter of Graduated's, so enacting a law that taxes dividends stays the way to tax profits properly); Proportional and Graduated keep their own range, and Traditionalism closes it, as the legislated code refuses a dividend tax there. The law collects none of it, so the entry declares a 22nd modifier, `te_tax_light_levy_div` (`tax_dividends_add` 0.025 × `te_tax_en_div`), whose value reads the rule and the marker, so it stops the day the code does. Its steps are Proportional's capped (2.5% on Very Low, 5% on Low), so it counts toward the tax level like any tax, at most to Low; it carries no relief and gives no view band. A player's starts at nothing, a save in progress included; an AI's follows its tax level (5% from Low up), and every change draws the dividend tax's own reactions (0 to 5% costs the Industrialists 2.5 approval before ideology). It carries over between laws that levy none and stops on a law that levies one, which brings its own rate; a tax level moved outside the code (an uprising's AI) clamps it to that level's rate, so it never holds the level up. Enacting or leaving Traditionalism syncs the code the same day. It collects: the owner read the Budget's Dividends Taxes line on 2026-11-16 ("I've confirmed that dividend taxes with the light code (and per capita taxes) appear to be working"). Its self-check, `TE_SELF_CHECK tax_light_div_levy`, read BROKEN in both games it ran in (0 of 70 levy countries in 1881, 0 of 92 in 1925, the control on a law's own rate matching): `modifier:tax_dividends_add` does not see a tax rate a journal entry declares, though the Budget collects it (`docs/guides/scripting_best_practices.md`, "A Tax Rate a Journal Entry Declares Is Collected but Invisible to `modifier:`"). It was retired the same day; no script check of the levy remains, since script can't measure collection. The play-test is `docs/testing/tax-code-playtest.md` § "The light code's low dividend tax". Tests: `test_tax_code_light_extra.py`.
