# What each event chain's triggers guarantee

The per-chain half of `loc_style_guide.md` § "What a chain's triggers already guarantee". That section holds the rule and the rows that apply to every chain; this file holds one row, or a few, for each chain, recorded by the writer who read its scripts during the rewrite of 2026-11-12 (#1539). The elections row and the rows written before that date stay in the guide.

**Use it before writing or changing a chain's text:** find the chain, read what a writer may assume and what looks safe but is not, and correct the row when the script changes. `python3 scripts/analysis/event_guarantees.py <event id or namespace>` prints an event's own technologies and trigger, and since #1622 the gates outside it: a law's unlocking technology and laws behind `is_enacting_law`, the `possible` of a journal entry that fires the event, a random pool's weights, a scripted trigger, the event that sends it. The rows below were written before it did, so where one says the tool finds no technology, run the tool: it still does not follow a decision, a button, a latch variable or a building's technology (the guide lists what it cannot). `event_guarantees.py --check-doc` lists every technology a row's Guaranteed column names that the tool finds guaranteed to no event of the row's chains; the rows are prose, so each finding is a row to read against the script, not an error.

A row is a reading of the script on the day it was written. Where a text depends on a guarantee, check the trigger again.
