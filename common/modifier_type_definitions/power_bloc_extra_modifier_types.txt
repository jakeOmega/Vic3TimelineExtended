# Monetary policy phase 5b — principle_group_monetary_union's DISPLAY FIELDS
# (docs/systems/monetary_policy_design.md §15A.3, §0.14). Nothing reads them:
# what the union does depends on who has ADOPTED, which no principle block can
# test, so script pays it (te_monetary_update_union and its neighbours) and
# reads the tier through has_principle. These only print the tier's terms
# under the principle's "Power Bloc" heading. test_monetary_union_leader.py
# holds every figure to the script value or static modifier that pays it.
#
# The rule (2026-11-15, owner): a figure is a numeric field the engine formats,
# never a number written into a name; a name is a short label; the conditions
# go in its _desc, and the rule a player plans around in a concept
# (concept_banking_common_currency, concept_banking_currency_reach). A bool is
# kept only for a rule with no quantity. modifier_name_audit enforces the names.
#
# The types are named for what they describe, not for a tier, so every tier
# restates and raises the same ones (principle_tier_audit). Each goes in the
# block whose heading names who gets it, so its name need not:
#   power_bloc_te_mon_currency_*  here, under "Power Bloc": every country USING
#                                 the common currency, each adopter and the
#                                 leader once one has
#   country_te_mon_swap_*,        banking_cycle_modifier_types.txt, in
#   country_te_mon_adopter_*      non_leader_modifier: what only members get
#   country_te_mon_issuer_*       the same file, in leader_modifier
# Each mirrors a modifier type the script applies, at the same scale, so its
# value is the applied figure.
