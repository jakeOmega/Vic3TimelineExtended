# Construction-market subsystem — the Construction Site's production methods.
#
# te_construction_market_site is the engine's construction camp
# (common/defines/te_construction_market_defines.txt): its inputs are bought
# only for the construction points actually spent, by the treasury or the
# investment pool according to which queue spends them. Two families of
# methods share its base group, and a mode group picks the family.
#
# MODE (pmg_te_construction_market_site_mode) — a one-way ratchet, the pattern
# documented in docs/guides/scripting_best_practices.md ("There Is No Engine
# PM Lock"):
#   pm_te_construction_mode_market  unlocks on { itself }
#   pm_te_construction_mode_direct  unlocks on { market, itself }
# A new site starts in market mode. Games with free_market_construction_rule
# disabled move every site to direct mode with activate_production_method
# (te_direct_construction_sync_site_pms), and market mode is then unreachable.
# In a market game, a site someone moves to direct mode by hand is removed and
# re-created by the weekly pulse (te_construction_market_reset_direct_sites).
#
# BASE (pmg_base_te_construction_market_site):
#   pm_te_construction_market_base    market mode: 1 construction good -> 1 point
#   pm_te_direct_construction_<tier>  direct mode: the goods a Construction
#       Sector of that tier buys for one unit of construction good
#       (extra_pms.txt input / output, 3 decimals) -> 1 point
# Every method is hidden when unavailable, so a site shows only its own family.
# The direct tier is the one delivering most of the country's construction
# (te_direct_construction_refresh_capacity), and throughput sizes every site
# the same way in both modes (te_construction_market_apply_per_site_modifier).
#
# The direct tiers mirror the sector tiers' inputs. When a sector tier's inputs
# change in extra_pms.txt, change the matching tier here too.
