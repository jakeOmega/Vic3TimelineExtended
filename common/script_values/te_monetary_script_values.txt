# ============================================================================
# Monetary Policy — script values
# ============================================================================
# Spec: docs/systems/monetary_policy_design.md (§4 rate stack, §7 risk premium,
# §8 stance + neutral rate, §9 inflation, §16 implementation mapping,
# §21 tuning constants).
#
# Everything here is evaluated in COUNTRY scope unless a comment says otherwise.
#
# UNIT CONVENTION. Every monetary variable and every script value below is in
# percentage POINTS (3.5 means 3.5%). Modifier fields use vanilla's interest
# scale (0.01 = 1pp), so a modifier contribution is read back as
# `100 x modifier:X` and written out as `multiplier = var:<pp value>` on a
# modifier whose field is 0.01.
#
# ----------------------------------------------------------------------------
# VARIABLE CONTRACT (§16.2) — country-scope variables owned by
# te_monetary_monthly_update. Every one of them initialises behind
# `has_variable` — with the single documented exception of te_rate_paid_rooted,
# whose absence is load-bearing — and NONE of them is ever removed (a `remove_variable` on a
# variable read by an `add_modifier { multiplier = ... }` is what
# modifier_multiplier_var_audit exists to catch). No new monetary variable may
# be introduced in je_banking.txt's `immediate` — that block resets unguarded
# and the JE is can_revolution_inherit.
#
#   te_policy_rate_target   regime range, integer   the dial's setting (§5)
#   te_policy_rate          regime range, fractional  drifts toward the target
#                                                   at 1/3 pp per month (2/3 digital)
#   te_mon_delegated        0 or 1                  1 = the target follows the mandate formula
#   te_mon_mandate          1-3                     1 price stability, 2 growth, 3 peg defence
#   te_premium_structural   floor to 30             what the country *is*; floored
#                                                   at 0.5 (0.25 under CBI)
#   te_premium_cyclical     -10 to 40               what is *happening*; added after the floor
#   te_rate_paid_pts        0.5 to 60               the displayed rate paid, clamped (§4)
#   te_rate_paid_applied    0.5 to 60               the value last written into
#                                                   te_monetary_rate_paid's multiplier.
#                                                   Equal to te_rate_paid_pts; it
#                                                   exists so step 9 can tell whether
#                                                   the rate has moved enough to be
#                                                   worth re-applying. A save from
#                                                   before the vanilla finance techs
#                                                   were cancelled engine-side may
#                                                   carry up to 10 more; the first
#                                                   pulse after loading corrects it.
#                                                   Never displayed; it is a
#                                                   bookkeeping value, not the rate.
#   te_rate_paid_rooted     1, or absent            THE ONE VARIABLE THAT IS
#                                                   DELIBERATELY NOT INITIALISED.
#                                                   Step 9 sets it only after a
#                                                   write whose ROOT was this
#                                                   country (`root ?= this`), so
#                                                   its ABSENCE is the signal
#                                                   that the interest modifier
#                                                   was applied from a root-less
#                                                   or foreign-rooted context and
#                                                   is therefore at the wrong
#                                                   multiplier. Initialising it
#                                                   would destroy that signal.
#                                                   Safe: it is read only through
#                                                   `has_variable`, never as
#                                                   `var:`, so it can never
#                                                   return 'none'. Never removed,
#                                                   like the rest.
#   te_neutral_rate         1 to 6      HIDDEN      r*, the natural rate (§8)
#   te_neutral_error        +/-1.5      HIDDEN      the country's estimate error
#                                                   (+/-0.5 under CBI); mandates
#                                                   and the displayed band use
#                                                   te_neutral_rate + te_neutral_error,
#                                                   never the true value
#   te_neutral_walk         see note    HIDDEN      the mean-reverting random-walk
#                                                   component of te_neutral_rate:
#                                                   +/-0.1 per month, mean-reverting,
#                                                   and bounded in effect by the
#                                                   1-6 clamp on te_neutral_rate.
#                                                   §16.2 gives no separate range
#   te_mon_gdp_last_year    >= 0                    cached gdp, refreshed yearly, for
#                                                   the neutral rate's growth term
#   te_mon_stance_gap       -10 to 10   HIDDEN      real rate minus neutral rate; 0 for
#                                                   every country without a dial (§8)
#   te_mon_stance_band      1 to 5      displayed   1 very loose ... 5 very tight
#   te_mon_regime           0 to 6                  0 none/bankless, 1 commodity, 2 gold,
#                                                   3 fiat, 4 digital, 5 crypto, 6 command
#
# PHASE 2 — INFLATION (§9). Same two rules: initialised behind `has_variable`,
# never removed. Step 6 of te_monetary_monthly_update is the only writer of
# every inflation variable below, exactly as step 8 is the only writer of the
# stance, with three documented exceptions:
#
#   * te_market_yield is owned by step 7, where §10's lenders' floor is
#     computed, and is not an inflation variable at all;
#   * te_inflation_band_applied and te_mon_hyper_cooldown are owned by step 6c,
#     the band swap, which is the half of step 6 that touches the engine; and
#   * the §9.2 HYPERINFLATION CRISIS (events/te_inflation_events.txt) writes
#     te_inflation, te_inflation_core, te_inflation_expected, te_cost_push,
#     te_monetisation_level, te_mon_dollarised and te_mon_hyper_cooldown in its

#     the reset from. The two share one effect, te_mon_effect_new_currency
#     (common/scripted_effects/te_monetary_effects.txt), so the price of issuing
#     a new currency is stated once. These are the only two places in the system
#     that write state the update otherwise integrates.
#
#   te_inflation            -10 to 100  displayed   headline annual inflation in pp:
#                                                   core plus cost-push (§9.3).
#                                                   Shown exactly on the dashboard
#   te_inflation_core       -10 to 100  HIDDEN      the slow-moving part, which
#                                                   persistence acts on and the
#                                                   mandates react to. Never printed:
#                                                   headline minus core is cost-push,
#                                                   and cost-push is public, so
#                                                   printing core would be harmless —
#                                                   but printing it NEXT to the
#                                                   pressure sum would not (P7), and
#                                                   one rule is easier to keep

#                                                   metallic regime

#                                                   pressure sum cannot be inverted
#                                                   to read the stance gap, the way
#                                                   bubble_pressure can be (§0.1)
#   te_cost_push            +/-6        displayed   the basket term added to HEADLINE
#                                                   (§9.3); a level, never cumulative
#   te_basket_index         -1 to 1                 this month's weighted price index
#                                                   for the country's market
#   te_basket_avg           -1 to 1                 the 1/36-a-month trailing average
#                                                   the index is differenced against
#   te_basket_seeded        0 or 1                  1 once te_basket_avg has been

#                                                   Without it month 1 reads the whole

#                                                   guard on has_variable
#   te_inflation_band       1 to 6      displayed   1 deflation, 2 comfort, 3 elevated,
#                                                   4 high, 5 very high, 6 hyperinflation
#                                                   (edges in te_mon_band_edge_* below)
#   te_inflation_band_applied 0 to 7                which member of the band family is
#                                                   currently on the country: 1-6 the
#                                                   matching te_inflation_band_* modifier,
#                                                   7 te_mon_dollarised_modifier (which
#                                                   REPLACES the band, so minting can
#                                                   never take -0.8 and -0.75 at once),
#                                                   0 = none applied yet. Bookkeeping
#                                                   for the swap in step 6c, never
#                                                   displayed
#   te_monetisation_level   0 to 3      displayed   the deficit-monetisation stepper (§11)
#   te_monetisation_minting_applied >= 0            the value last written into

#                                                   BACKS A MULTIPLIER — never remove it
#   te_mon_dollarised       0 or 1                  1 once the country abandoned its
#                                                   currency out of hyperinflation
#                                                   (ruling P9). Makes te_mon_has_dial

#                                                   (te_banking_law_change_cleanup).
#                                                   te_inflation.1's dollarise option sets

# HIDDEN STATE RULE (§8). te_neutral_rate, te_neutral_error, te_neutral_walk and
# te_mon_stance_gap are never printed in any tooltip, loc string or visible
# modifier. What the player *chooses* is shown exactly; the economy's hidden
# state is not. The displayed stance band is the only window onto the gap.
# Phase 2 adds three more to the list (ruling P7): te_inflation_core,
# te_inflation_noise, and the §9.1 pressure SUM, which is never stored but must
# not be rendered from its parts either — it carries -0.4 x the stance gap, so a
# printed sum inverts to r* exactly the way bubble_pressure does (§0.1). What
# phase 2 shows exactly: headline inflation, expected inflation, the target, the
# rate paid, the monetisation level, and the two pressure modifier types, which
# are what the player chose. The console debug event is the one place the hidden
# half may be printed.

# documented exception to the single-owner rule, alongside the §9.2 crisis and
# the P9 dollarisation exit — and unlike those two it is unreachable from play:
# nothing in the mod fires either event. The harness exists because every AI
# country is delegated, so no observer run ever exercises the manual path §9.1
# calls unstable by design.

# --- Reference rate ---------------------------------------------------------

# The long-run real rate the whole world borrows against: 3.0 in eras 1-4,
# 2.5 in eras 5-8, 2.0 in eras 9-12 (§8). In phase 1 this doubles as the world
# / reference rate (§12.1) and as the base of the hidden neutral rate.
#
# ERA DETECTION. The engine exposes no "current era" trigger and the mod has no
# canonical era detector, so this reuses the mod's two existing idioms: an era
# is marked by a signature technology (events/modern_election_events.txt:1000),
# and "the world has reached era N" is asked as "some great power has researched
# it" (common/script_values/extra_script_values.txt:870-949). The markers are
# `macroeconomics` (era_5) and `globalization` (era_9), both society techs and
# neither of them a capital-market-access tech, so nothing is double-counted
# against te_mon_access_premium.
#
# This is deliberately a WORLD quantity, not a per-country one: the spec calls
# it the world / reference rate (§7.4, §12.1, §21), and the neutral rate is then
# world base + per-country deviation (growth term + walk). Anchoring on great
# powers also removes the fragility of a single-tech test — some great power
# will always have researched the marker even if a given country skipped it.
#
# COST. The two any_country scans make this expensive to call per country per
# pulse, so task 2 does not: te_monetary_refresh_world_era_base evaluates it
# ONCE A MONTH into global_var:te_mon_era_base_world (on_monthly_pulse, plus
# on_game_started and a self-heal inside the country update), and every country
# reads the global. Nothing else should call this value directly in a per-country
# loop.
te_mon_era_base = {
	value = 3.0
	if = {
		limit = {
			any_country = {
				country_rank >= rank_value:great_power
				has_technology_researched = macroeconomics
			}
		}
		subtract = 0.5
	}
	if = {
		limit = {
			any_country = {
				country_rank >= rank_value:great_power
				has_technology_researched = globalization
			}
		}
		subtract = 0.5
	}
}


# --- The dial's range (§5.1) ------------------------------------------------

# The lowest and highest target the current monetary regime allows, in pp.
#
#   gold standard        the reference rate +/- 2, taken inwards to whole
#                        numbers and held inside 0-15 (the phase-1 interim rule
#                        of §19 row 1, standing in for §12's gold flows)
#   digital currency     -3 to 25 (no cash to hoard, so negative rates bite)
#   fiat currency        0 to 25
#
# ONE AUTHORITY, TWO CONSUMERS. te_monetary_clamp_target re-clamps the target
# every month, and the dashboard's stepper has to grey out at exactly the same
# edges (te_mon_target_can_step_down / _up in
# common/scripted_triggers/te_monetary_triggers.txt). Writing the table twice is
# how the stepper ends up offering a step the monthly update silently undoes, so
# both read these two values and nothing else states the bounds.
#
# The gold branch is guarded on te_mon_era_base_now because a country that has
# never run a monetary pulse has no cached reference rate. Inside
# te_monetary_clamp_target that cannot happen (step 0 writes it every pulse); in
# the GUI it can, on a save from before the system existed, and the fiat range it
# falls back to is the harmless answer — the dashboard's readiness gate hides the
# stepper until the first pulse anyway.
#
# THE FLOOR IS DECLARATIVE. Everything except the gold band comes from
# country_policy_rate_floor_add, which law_digital_currency carries at -0.03 and
# every other regime leaves at zero. The law tooltip therefore states the rule
# ("Lowest Policy Rate -3%") instead of a sentence of localization restating a
# law check that lived here. The gold band stays scripted because it is a
# phase-1 INTERIM rule standing in for §12's gold flows (§19 row 1), not a
# property of the law — when gold flows arrive, the band is computed from
# reserves and this branch goes with it.
te_mon_target_min = {
	value = 0
	if = {
		limit = {
			has_law_or_variant = law_type:law_gold_standard
			has_variable = te_mon_era_base_now
		}
		add = {
			value = var:te_mon_era_base_now
			subtract = 2
			min = 0
			ceiling = yes
		}
	}
	else = {
		add = {
			value = modifier:country_policy_rate_floor_add
			multiply = 100
		}
	}
}

# The rate at or below which the policy rate counts as "at the floor" — the gate
# on open market operations (te_mon_policy_rate_at_floor). One point of slack,
# because te_policy_rate drifts fractionally and need not land exactly on the
# bound.
#
# ONLY FIAT AND DIGITAL EVER READ THIS. Open-market operations are fiat/digital
# only (§0.1 ruling of 2026-09-20: creating unbacked money to buy bonds is what
# a convertibility promise forbids), and the regime is checked before the floor
# is, so te_mon_target_min here is always its country_policy_rate_floor_add
# branch — 0 under fiat, -3 under digital. A `max = 0` used to sit here for the
# sole purpose of stopping a gold standard's band floor (reference rate - 2,
# around 1pp) from counting as "the rate can go no lower"; the regime gate does
# that job now, and gold never reaches this value.
te_mon_floor_threshold = {
	value = te_mon_target_min
	add = 0.01
}

te_mon_target_max = {
	value = 0
	if = {
		limit = {
			has_law_or_variant = law_type:law_gold_standard
			has_variable = te_mon_era_base_now
		}
		add = {
			value = var:te_mon_era_base_now
			add = 2
			max = 15
			floor = yes
		}
	}
	else = {
		add = 25
	}
}


# --- How fast the rate closes on the target (§5.1) --------------------------

# The multiplier on the baseline drift speed, from
# country_policy_rate_drift_speed_mult. law_digital_currency carries +1.0, so a
# digital regime moves at 2x — which is the whole of the old
# `if = { limit = { has_law_or_variant = law_type:law_digital_currency } }`
# branch inside te_monetary_drift_policy_rate, now stated on the law's own
# tooltip instead of in a sentence of localization.
#
# `min = 0.1` stops a hypothetical -100% grant freezing the rate forever; the
# dial would otherwise become a control that silently does nothing.
te_mon_drift_speed_factor = {
	value = 1
	add = modifier:country_policy_rate_drift_speed_mult
	min = 0.1
}

# How far the policy rate moves toward its target in one month, in pp. A third
# of a point at the baseline — a point a quarter, so a 5pp swing takes fifteen
# months and reversals are slow by construction (§4). Rendered in the dashboard's
# Policy Rate and Rate Target tooltips, so the player reads the real number
# rather than prose about thirds.
te_mon_drift_step = {
	value = 0.3333
	multiply = te_mon_drift_speed_factor
}

# The distance that has to remain before another step is worth taking, rather
# than snapping to the target.
#
# THE EPSILON IS LOAD-BEARING. Comparing against the bare step lets a hairline
# remainder buy a whole extra month: closing a 1.0pp gap in thirds leaves
# 1.0 - 2 x 0.3333 = 0.3334, which is *greater* than 0.3333, so the rate takes a
# fourth step of 0.3333 to land 0.0001 short and snaps on the fifth month. The
# old hard-coded thresholds (0.34 against a 0.3333 step, 0.67 against 0.6667)
# existed precisely to stop that, and 0.0067 reproduces the first of them
# exactly. A 1pp move is three months at the baseline, as it always was.
te_mon_drift_step_threshold = {
	value = te_mon_drift_step
	add = 0.0067
}

# The same threshold, negated, so te_monetary_drift_policy_rate can test the
# downward side without a third scratch variable.
te_mon_drift_step_threshold_neg = {
	value = te_mon_drift_step_threshold
	multiply = -1
}


# --- Structural premium terms -----------------------------------------------

# Capital-market access premium, in pp (§7.2). This is what keeps Siam or
# Afghanistan out of the London market: a permanent premium that shrinks as a
# country builds financial institutions. It replaces vanilla's five flat -2pp
# tech reductions (which are cancelled engine-side by
# common/technology/technologies/te_monetary_tech_injections.txt) and is
# deliberately front-loaded, because Britain in 1836 holds only two of the five
# techs and must still land near Consols.
#
#   base, no finance techs           +8.0
#   banking                          -4.0
#   central_banking                  -2.5
#   mutual_funds                     -0.5
#   international_exchange_standards -0.5
#   modern_financial_instruments     -0.5
#   no stock_exchange                +2.0
#
# The surcharge keys on the `stock_exchange` technology, not on having the
# stock-exchange journal entry: that JE's other gate (a level-10 urban centre)
# is not a capital-market signal.
#
# Anchors (§7.4): Britain / USA 1836 hold banking + central_banking + the
# exchange, so 8 - 4 - 2.5 = 1.5. Siam 1850 holds none of them and no exchange,
# so 8 + 2 = 10.
#
# Consumed by te_monetary_monthly_update step 5 as part of the STRUCTURAL tier,
# i.e. before the 0.5pp (0.25pp under CBI) floor is applied.
te_mon_access_premium = {
	value = 8
	if = {
		limit = { has_technology_researched = banking }
		subtract = 4
	}
	if = {
		limit = { has_technology_researched = central_banking }
		subtract = 2.5
	}
	if = {
		limit = { has_technology_researched = mutual_funds }
		subtract = 0.5
	}
	if = {
		limit = { has_technology_researched = international_exchange_standards }
		subtract = 0.5
	}
	if = {
		limit = { has_technology_researched = modern_financial_instruments }
		subtract = 0.5
	}
	if = {
		limit = { NOT = { has_technology_researched = stock_exchange } }
		add = 2
	}
}

# The lowest structural premium lenders will offer, in pp (§7.1). Standing
# earned past it buys nothing: credibility has a lower bound.
#
# 0.5 baseline, moved by country_credit_standing_floor_add, which
# law_central_bank_independence carries at -0.0025 (-0.25pp). That grant is the
# whole of the old `te_mon_is_cbi` branch inside te_monetary_update_premium, and
# it now shows on the law's own tooltip beside the -0.5pp credibility term it is
# separate from and stacks with.
#
# Also rendered in the dashboard's Credit Standing tooltip, so the figure the
# player reads is the one the premium is actually floored at.
te_mon_standing_floor = {
	value = 0.5
	add = {
		value = modifier:country_credit_standing_floor_add
		multiply = 100
	}
	min = 0
}

# --- Cyclical premium terms -------------------------------------------------

# Debt-load premium, in pp (§7.6). Zero below scaled_debt 0.25, then linear to
# +4pp at scaled_debt 1.0 and flat above it. Lenders price a heavily indebted
# borrower higher; this is what keeps a cheap-debt world self-limiting.
#
# CYCLICAL, so it is added after the structural floor and always bites.
#
# Arithmetic: (scaled_debt - 0.25) x 16 / 3 is (scaled_debt - 0.25) x 5.3333
# without the rounding. `scaled_debt` is a country trigger read, which is legal
# inside a script value but NOT in a change_variable op slot — that is exactly
# why this is a named script value.
te_mon_scaled_debt_premium = {
	value = scaled_debt
	subtract = 0.25
	multiply = 16
	divide = 3
	min = 0
	max = 4
}

# How hard a delegated central bank leans against the financial cycle, in pp
# (§6). This is the replacement for the deleted rate-hike button's AI logic:
#
#   frenzy                  +2
#   boom                    +1
#   bubble pressure >= 65   +1   (on top of the phase term)
#   downturn                -2
#   panic                   -3
#
# Price stability takes the whole lean; growth takes half of it; peg defence
# ignores the domestic cycle entirely.
#
# finance_cycle_value and bubble_pressure are COUNTRY variables owned by
# je_banking_cycle's `immediate` (je_banking.txt:119-133) — the same variables
# harvest conditions read through `owner = { ... }`. A country without the
# journal entry has neither, so every branch carries its own has_variable guard
# and such a country simply leans by 0. The banking_cycle_is_* triggers are the
# canonical phase thresholds (market_triggers.txt:2-8); they read
# var:finance_cycle_value unguarded, which is why the guard is in the limit
# beside them rather than around them.
te_mon_cycle_lean = {
	value = 0
	if = {
		limit = {
			has_variable = finance_cycle_value
			banking_cycle_is_frenzy = yes
		}
		add = 2
	}
	else_if = {
		limit = {
			has_variable = finance_cycle_value
			banking_cycle_is_boom = yes
		}
		add = 1
	}
	else_if = {
		limit = {
			has_variable = finance_cycle_value
			banking_cycle_is_panic = yes
		}
		subtract = 3
	}
	else_if = {
		limit = {
			has_variable = finance_cycle_value
			banking_cycle_is_downturn = yes
		}
		subtract = 2
	}
	if = {
		limit = {
			has_variable = bubble_pressure
			var:bubble_pressure >= 65
		}
		add = 1
	}
}

# --- The stance channel into the banking cycle (§8, §16.3) ------------------

# The stance gap, clamped to +/-4 for the purpose of pushing the cycle.
#
# The gap itself is clamped to +/-10 (§8); this tighter bound is the one the
# cycle sees, so that a country parked at an extreme stance settles at the edge
# of the +/-5 momentum bar rather than driving through it: +/-4 x -0.125 is
# -/+0.5 a month against a 10%-a-month decay, i.e. a steady state of -/+5.
#
# GUARDED. te_mon_stance_gap does not exist until a country's first monthly
# monetary update, and the journal-entry pulse and that update may run in either
# order in a given month (§17 check 7) — so a missing variable reads as 0 (no
# push) and a present one may be a month old, which is exactly what §16.3 says
# the consumer must tolerate. A country without a dial has a gap of exactly 0.
#
# HIDDEN STATE. Neither this value nor the two below may ever be rendered: they
# are the gap, and the gap is r* (§8, "Why not a scaled modifier"). They are
# consumed only by `change_variable` inside banking_cycle_advance_variables.
#
# DO NOT FOLD THE TWO MULTIPLIERS BELOW INTO THIS CLAMP BLOCK. A script value's
# keys apply in the order they are written, so a `multiply` placed ahead of
# `min`/`max` inside the same block silently DISARMS the bound: it is then tested
# against the already-scaled figure. Folding `multiply = -0.125` in above the
# bounds here would leave a +/-4 clamp guarding a quantity whose entire range is
# +/-1.25, so the clamp would never bite and a country parked at an extreme
# stance would push momentum by up to 1.25 a month instead of the calibrated 0.5
# — straight through the +/-5 momentum bar the steady state below assumes.
# Keep the clamp and the scaling in separate script values, as they are here.
te_mon_stance_gap_clamped = {
	value = 0
	if = {
		limit = { has_variable = te_mon_stance_gap }
		add = {
			value = var:te_mon_stance_gap
			min = -4
			max = 4
		}
	}
}

# Monthly push on finance_cycle_momentum: -0.125 per pp of tight gap (§8).
# Calibration: a 2pp tight stance equals the deleted rate-hike tool's -0.25.
te_mon_stance_momentum_add = {
	value = te_mon_stance_gap_clamped
	multiply = -0.125
}

# Monthly push on bubble_pressure: -0.75 per pp of tight gap (§8).
# Calibration: 2pp is about -1.5, against the old hike's -2.0 and the old open
# market operations' +0.8.
te_mon_stance_bubble_add = {
	value = te_mon_stance_gap_clamped
	multiply = -0.75
}

# The credibility anchor c (§9.1, §21): how much of expected inflation comes
# from the target rather than from what inflation is actually doing. With a
# standing pressure P and the real stance held, inflation settles at
# anchor + P / c, so c is the whole difference between a labour law costing
# 0.7pp and costing 3.3pp.
#
#   metallic (gold / commodity)  1      convertibility IS the anchor; §9.1 pins
#                                       expectations to 0 outright
#   state-owned banking          0.15   the weakest anchor there is (§5.2): a
#                                       bank the treasury owns cannot promise
#                                       anything the treasury might want undone
#   central bank independence    0.7
#   delegated, not independent   0.4
#   manual                       0.25   unstable above the floor BY DESIGN — the
#                                       Taylor principle; holding a nominal rate
#                                       fixed while inflation rises eases policy
#
# ORDER OF THE BRANCHES IS A RULING, not an accident. State-owned banking sits
# above both independence and delegation: it is in the same law group as
# independence (so those two can never both hold), but a state-owned bank CAN be
# delegated, and delegating the dial to a bank the government owns does not buy
# credibility it never had. Delegation is read through te_mon_is_delegated,
# which is guarded — a country that has never pulsed reads as manual.
te_mon_credibility_c = {
	if = {
		limit = { te_mon_is_metallic = yes }
		value = 1
	}
	else_if = {
		limit = { te_mon_is_state_banking = yes }
		value = 0.15
	}
	else_if = {
		limit = { te_mon_is_cbi = yes }
		value = 0.7
	}
	else_if = {
		limit = { te_mon_is_delegated = yes }
		value = 0.4
	}
	else = {
		value = 0.25
	}
}

# THE IDIOM IS st_res_<good>_price_rel's (common/script_values/st_res_script_values.txt,
# rationale in docs/systems/strategic_reserve_system.md § "The price signal").
# Each value is the signed premium against the good's base price on the
# country's own market, as a fraction: -0.12 is 12% below base.
#
#   max(market_goods_pricier, 0) - max(market_goods_cheaper, 0)
#
# written as `value = 0`, the market read, `min = 0` (that is the max-with-zero
# clamp), then a `subtract` block of the same shape. The engine docs do not
# settle whether the two reads are clamped at zero or are signed mirrors of
# each other, and this expression is correct either way. Do NOT simplify it to
# a bare market_goods_pricier read, and do NOT rewrite the reads as a
# `this.market.mg:<good>` dot chain: no vanilla file reads through `mg:` that
# way and a chain that silently returned zero would look exactly like a market
# sitting at base price.
#
# WHY THESE ARE NOT st_res_grain_price_rel / st_res_oil_price_rel. The reserve
# defines two of the basket's eight goods and would have to define the other
# six for goods it does not stockpile. Eight values under one prefix, retuned
# and read as one set, beats a basket that breaks the day the Strategic Reserve
# drops a good.
#
# UNGUARDED ON PURPOSE. te_mon_basket_index_value below gates each term on the
# market actually trading the good; these raw reads are also printed one by one
# by te_debug_monetary.1, where an engine complaint about `mg:oil` in a market
# that has never traded oil is the ANSWER to §9.3's open question, not a bug.

		value = 0

# index = SUM( weight x (price / base - 1) ) over the eight goods (§9.3):
#
#   grain .30 | clothes .15 | coal .15 | oil .15
#   fish .075 | meat .075   | wood .05 | fabric .05        (they sum to 1.00)
#
# THE WEIGHTS LIVE HERE AND NOWHERE ELSE. They are literals rather than eight
# named constants because they are one table, meaningless apart, and §21 does
# not tune them individually.
#
# EACH TERM IS GATED on the market actually supplying the good, using the
# guard the mod already uses for exactly this question
# (common/mobilization_options/extra_mobilization_options.txt:5-12:
# `market ?= { mg:<good> = { market_goods_sell_orders > 0 } }`). A good the
# market has never traded contributes 0 rather than erroring — and that is the
# right economics as well as the safe read: the price of a good nobody in your
# market supplies is not a cost your economy is paying. The weights are NOT
# renormalised over the surviving goods; an economy with no oil trade has a
# genuinely smaller basket.
#
# ORDER INSIDE EACH TERM: the `min = 0` clamps inside te_mon_price_rel_<good>
# run before the weight is applied here, which is the right way round — see the
# "DO NOT FOLD THE TWO MULTIPLIERS INTO THIS CLAMP BLOCK" note above
# te_mon_stance_gap_clamped for what folding a multiply ahead of a bound costs.
te_mon_basket_index_value = {
	value = 0
	if = {
		limit = { market ?= { mg:grain = { market_goods_sell_orders > 0 } } }
		add = {
			value = te_mon_price_rel_grain
			multiply = 0.30
		}
	}
	if = {
		limit = { market ?= { mg:clothes = { market_goods_sell_orders > 0 } } }
		add = {
			value = te_mon_price_rel_clothes
			multiply = 0.15
		}
	}
	if = {
		limit = { market ?= { mg:coal = { market_goods_sell_orders > 0 } } }
		add = {
			value = te_mon_price_rel_coal
			multiply = 0.15
		}
	}
	if = {
		limit = { market ?= { mg:oil = { market_goods_sell_orders > 0 } } }
		add = {
			value = te_mon_price_rel_oil
			multiply = 0.15
		}
	}
	if = {
		limit = { market ?= { mg:fish = { market_goods_sell_orders > 0 } } }
		add = {
			value = te_mon_price_rel_fish
			multiply = 0.075
		}
	}
	if = {
		limit = { market ?= { mg:meat = { market_goods_sell_orders > 0 } } }
		add = {
			value = te_mon_price_rel_meat
			multiply = 0.075
		}
	}
	if = {
		limit = { market ?= { mg:wood = { market_goods_sell_orders > 0 } } }

			multiply = 0.05

		}
	}

# eight price reads are done once by the market owner and copied by everybody
# else. Block form (`market = { owner = { ... } }`) rather than a

# How far above 1% of GDP a year the deficit has to be before it prices
# anything (§9.1). Same shape as te_mon_unanchored_tolerance: inside the
# tolerance, an ordinary working deficit costs nothing.
te_mon_deficit_tolerance = {
	value = 1
}

# The deficit as a % of GDP a year (ruling P4). Shape borrowed from
# financial_cycle_government_fiscal_policy_effect_size
# (common/script_values/extra_script_values.txt), with two differences:
#
#   * the flows are annualised by te_mon_deficit_annualise_factor (52) before
#     the division, because `income` and `total_expenses` are WEEKLY while
#     `gdp` is annual. The engine's own event-target catalogue says so for two
#     of the three — docs/engine/event_targets_summary.txt: "income … Get the
#     current weekly income of the scoped country" and "gdp … Get the scoped
#     country's yearly predicted GDP" — which is as far as §17 check 12 can be
#     settled from the files; total_expenses is documented only as a trigger
#     and is assumed to share income's cadence; and
#   * the monetisation the country is running is ADDED BACK, because no trigger
#     reads minting and money-financed spending would otherwise suppress its
#     own deficit term. One monetisation level is 1% of GDP a year
#     (te_mon_monetisation_gdp_share), i.e. exactly one point of this figure.
#
# Cached into te_mon_deficit_pct by step 6 and printed by the console read-out,
# so the units question can be settled from a running game.
te_mon_deficit_pct_value = {
	value = total_expenses
	subtract = income
	multiply = te_mon_deficit_annualise_factor
	divide = {
		value = gdp
		min = 1
	}
	multiply = 100
	if = {
		limit = { has_variable = te_monetisation_level }
		add = {
			value = var:te_monetisation_level
			multiply = te_mon_monetisation_gdp_share
			multiply = 100
		}
	}
}

# Everything script grants as standing pressure, in pp. TWO TYPES, not one
# (ruling P11): country_wage_pressure_add is what labour and welfare laws carry
# and what the §9.4 real-wage dividend pays back on, country_inflation_pressure_add
# is everything else (events, devaluations). §9.1 sums them; only the dividend
# tells them apart. Both are modifier fields on vanilla's scale, so 0.01 = 1pp
# and each half is read back x 100.
#
# THE SUM IS DEFINED FROM THE TWO HALVES rather than re-reading both fields,
# because the halves are what the dashboard prints: both are things the player
# CHOSE (a labour law, a devaluation, a monetisation step), so §0's hidden-state

# definition per modifier field means the rows and the engine can never drift.
te_mon_wage_pressure_display = {
	value = 0
	add = modifier:country_wage_pressure_add
	multiply = 100
}

te_mon_other_pressure_display = {
	value = 0
	add = modifier:country_inflation_pressure_add
	multiply = 100
}

te_mon_pressure_modifiers = {
	value = te_mon_wage_pressure_display
	add = te_mon_other_pressure_display
}

# The POSITIVE half of wage pressure, in pp (§9.4). Both things that treat
# wages asymmetrically read this one value rather than writing the clamp
# twice: the wage-price spiral below, and te_mon_wage_dividend_units further
# down. A country whose labour laws SUPPRESS wages (no workers' rights,
# combination acts, anti-strike laws) reads 0 from both — it neither earns a
# dividend for holding wages down nor spirals on the way up. Its negative
# contribution to inflation is already in te_mon_pressure_modifiers above, and
# counting it a second time would make wage suppression a disinflation tool
# that gets stronger the worse inflation is.
te_mon_wage_pressure_positive = {
	value = 0
	add = modifier:country_wage_pressure_add
	multiply = 100
	min = 0
}

# The wage-price spiral (§9.4): above 8% headline, the same labour and welfare
# laws add their pressure A SECOND TIME. Wage pressure is a level — how far
# above expectations inflation settles — and the point of the spiral is that
# once prices are moving fast enough for everyone to be watching them, the
# bargaining that produced that level starts producing it again on top of
# itself. It is also what makes §10's "never disinflate" path expensive: a
# country that lets inflation run past the high band with strong labour laws
# has doubled the term it would have to unwind.
#
# THE GATE IS LAST MONTH'S HEADLINE. te_mon_pressure_total is evaluated in step
# 6b to advance core, BEFORE the same step writes this month's headline and
# band — so var:te_inflation here is the figure the player was shown last
# month. That is the same one-month lag ruling P5 already accepts for the
# stance gap, and the threshold is te_mon_band_edge_high rather than a literal
# 8 so the spiral opens exactly where the "high" band does.
te_mon_pressure_wage_spiral = {
	value = 0
	if = {
		limit = {
			has_variable = te_inflation
			var:te_inflation >= te_mon_band_edge_high
		}
		add = te_mon_wage_pressure_positive
	}
}

# The hidden mean-reverting random walk (ruling P7). It exists so the pressure
# sum cannot be inverted to read the stance gap: every other term is either
# public or derivable, so without a random component two months of a displayed
# headline would recover r*. Step 6 advances it; this only reads it.
te_mon_pressure_noise = {
	value = 0
	if = {
		limit = { has_variable = te_inflation_noise }
		add = var:te_inflation_noise
	}
}

# The regime pull (§9.1). A convertible currency drags core inflation back to
# zero — that is the deflation bias of hard money, expressed as a pressure term
# rather than a constant — and a currency nobody issues drags harder still.
#
#   gold / commodity money, and a DOLLARISED country (ruling P9: it now uses
#   somebody else's metal-or-otherwise disciplined money)   -pi_core
#   decentralized cryptocurrency                            -(pi_core + 1)
#
# Dollarisation is tested first so a dollarised crypto country gets the
# metallic pull rather than the crypto one: the currency actually circulating
# is the foreign one. The §9.1 gold-SUPPLY term is deliberately absent — it is
# a phase-3 companion to gold flows (ruling P2), and this plain pull carries
# the deflation bias until then.
te_mon_pressure_regime_pull = {
	value = 0
	if = {
		limit = {
			OR = {
				te_mon_is_metallic = yes
				AND = {
					has_variable = te_mon_dollarised
					var:te_mon_dollarised = 1
				}
			}
		}
		subtract = te_mon_inflation_core_read
	}
	else_if = {
		limit = { has_law_or_variant = law_type:law_decentralized_cryptocurrency }
		subtract = te_mon_inflation_core_read
		subtract = 1
	}
}

# The whole §9.1 pressure, in pp: how far above expectations inflation settles
# while all of this lasts. A LEVEL, never a per-month increment.
#
# THE GOLD-FLOW TERM IS ABSENT ON PURPOSE (phase 3, ruling P2), as is the
# gold-supply term folded into the regime pull above.
te_mon_pressure_total = {
	value = te_mon_pressure_stance
	add = te_mon_phase_pressure
	add = te_mon_pressure_bubble
	add = te_mon_pressure_deficit
	add = te_mon_pressure_monetisation
	add = te_mon_pressure_qe
	add = te_mon_pressure_modifiers
	add = te_mon_pressure_wage_spiral
	add = te_mon_pressure_noise
	add = te_mon_pressure_regime_pull
}


# --- The real-wage dividend: the multiplier (§9.4) ---------------------------

# What te_mon_real_wage_dividend's multiplier is set to: ONE UNIT PER +0.1pp of
# positive wage pressure. law_factory_councils alone (+0.5pp) is 5 units, worth
# +0.15 financial momentum a month and -0.1 on lower-strata expectations; a
# country stacking factory councils, workers' protections and a universal basic
# income (+1.4pp) is 14 units, the realistic ceiling.
#
# WHY THE DIVIDEND IS PAID ON WAGE PRESSURE AND NOT ON THE WHOLE SUM. Step 6d
# is paying for wage-led demand — higher real wages spent — which is a fact
# about the labour laws and about nothing else in te_mon_pressure_total. A
# devaluation or a monetised war raises prices without raising anybody's pay,
# and paying a dividend on those would reward debasing the currency. That is
# the whole reason ruling P11 split the two modifier types.
#
# Step 6d of the monthly update writes this into te_mon_wage_dividend_applied
# and nothing else reads it.
te_mon_wage_dividend_units = {
	value = te_mon_wage_pressure_positive
	multiply = te_mon_wage_dividend_units_per_pp
}

# Units of dividend per pp of wage pressure. 10 is §9.4's "each +0.1pp", named
# rather than inlined so retuning the dividend's granularity is a one-line edit
# (§21) — though the modifier's own field values are the sharper dial.
te_mon_wage_dividend_units_per_pp = {
	value = 10
}


# --- Monetisation: the minting amount (§11) ---------------------------------

# What te_monetisation_minting's multiplier is set to, in pounds of extra
# minting a WEEK:
#
#   level x te_mon_monetisation_gdp_share x gdp / te_mon_weeks_per_year
#
# i.e. one level is 1% of annual GDP a year, spread over the 52 weekly minting
# ticks the engine actually pays it out on. Step 1b of the monthly update
# writes this into te_monetisation_minting_applied and nothing else reads it.
#
# THE SHAPE IS te_mon_pressure_monetisation'S, not a fresh one: the level is
# folded in behind has_variable so a country that has never pulsed contributes
# a clean zero instead of 'none', and `multiply = gdp` is the bare trigger read
# the mod already relies on in common/treaty_articles/05_transfer_money.txt.
#
# SANITY CHECK against the mod's own GDP-scaled money flows:
# sv_money_flow_event_small is gdp x 0.0001 a week, i.e. 0.52% of GDP a year,
# so one monetisation level is a little under twice the largest one-off flow a
# law event grants. Against vanilla seigniorage (~5.2% of GDP a year up to the
# GDP-200M cap, §11) it is the "+20% of baseline minting per level" §11 asks
# for — and past that cap, where baseline minting is a flat ~£10.4M a year, it
# keeps growing with the economy. That is the whole reason §11 chose a
# GDP-scaled `_add` over country_minting_mult.
te_mon_monetisation_minting_value = {
	value = 0
	if = {
		limit = { has_variable = te_monetisation_level }
		add = var:te_monetisation_level
	}
	multiply = te_mon_monetisation_gdp_share
	multiply = gdp
	divide = te_mon_weeks_per_year
}


# --- Expectations: the credibility blend (§9.1) -----------------------------

# |headline - anchor|, in pp. change_variable has no absolute value and a
# script value's `limit` tests triggers on the scope rather than the running
# total, so the sign is decided from the inputs and each branch subtracts the
# other way round.
te_mon_inflation_gap_abs = {
	value = 0
	if = {
		limit = {
			has_variable = te_inflation
			var:te_inflation > te_mon_inflation_anchor
		}
		add = var:te_inflation
		subtract = te_mon_inflation_anchor
	}
	else_if = {
		limit = { has_variable = te_inflation }
		add = te_mon_inflation_anchor
		subtract = var:te_inflation
	}
}

# c_eff = c x max( 0 , 1 - |headline - anchor| / 10 ) — credibility is lost as
# inflation leaves target, and is gone entirely 10pp away from it (§9.1).
# Without it an anchored `expected` would trail a STEADY high inflation for
# ever and §10's lenders' floor would under-price it permanently.
#
# METALLIC MONEY IS EXEMPT — convertibility IS the anchor — and step 6 carries
# that exemption rather than this value: a metallic regime never reaches the
# expectations blend at all, because §9.1 pins its expectations to 0 outright
# (the table's "—" for alpha). If that pin is ever softened into an ordinary
# c = 1 update, the exemption has to reappear here as a branch.
te_mon_credibility_eff = {
	value = 1
	subtract = {
		value = te_mon_inflation_gap_abs
		divide = te_mon_deanchor_span
	}
	min = 0
	multiply = te_mon_credibility_c
}

# (1 - c_eff) x headline + c_eff x anchor — what expectations are moving
# toward this month, before alpha decides how far they get (§9.1).
te_mon_expectation_target = {
	value = te_mon_inflation_read
	multiply = {
		value = 1
		subtract = te_mon_credibility_eff
	}
	add = {
		value = te_mon_inflation_anchor
		multiply = te_mon_credibility_eff
	}
}


# ============================================================================
# PHASE 2 — THE RATE STACK: what steps 2, 5 and 7 read (§6, §7.6, §10)
# ============================================================================
# Inflation reaching the rest of the stack. §6 gives the mandates their pi
# terms, §7.6 gives the cyclical premium two more terms, and §10 gives the rate
# paid its lenders' floor. Only the pieces change_variable cannot express live
# here: a max() against zero, an absolute value, and the §21 constants
# themselves.
#
# ORDER OF KEYS. Every computed value below puts the BOUND before the SCALING,
# for the reason spelled out on te_mon_stance_gap_clamped: a script value's
# keys apply in the order they are written, so a `multiply` placed above a
# `min` is tested against the already-scaled figure and silently disarms it.
#
# WHAT IS HIDDEN HERE. The two mandate reaction terms read te_inflation_core,
# which is hidden state (ruling P7), and their consumer adds them to r^*. The
# two premium terms are the opposite: expected inflation, the anchor and the
# monetisation level are all displayed exactly, so those two are printed on the
# dashboard's Risk Premium tooltip.


# --- The mandate's inflation terms (§6, §21) --------------------------------

# How hard price stability leans on the inflation gap:
#   target = r^* + pi + 1.0 x (pi - anchor) + cycle_lean
# The second pi term is what makes the mandate move MORE than one for one with
# inflation. That is the Taylor principle, and it is the whole reason a
# delegated bank can disinflate where a fixed manual target cannot (§9.1).
te_mon_mandate_inflation_weight = {
	value = 1.0
}

# Growth's standing looseness in pp (§6, §21): it sits a point below price
# stability's neutral setting by design — more momentum, faster bubbles, more
# crashes. NEGATIVE, because the consumer adds it rather than subtracting it,
# so the sign lives in one place.
te_mon_mandate_growth_bias = {
	value = -1.0
}

# How hard the growth mandate reacts to inflation once it is past the threshold
# below — half price stability's weight (§6, §21).
te_mon_mandate_growth_reaction = {
	value = 0.5
}

# Where growth starts reacting to inflation at all, in pp (§6, §21). Below it
# the mandate does not see inflation; with the reaction above, its zero-gap
# point is pi = 6.
#
# NOT DEFINED FROM te_mon_inflation_anchor. §21 lists it as its own constant,
# and the two mean different things: the anchor is the target inflation is
# steered TO, this is the tolerance before a growth-minded bank stops
# tolerating. A metallic regime never runs this mandate in any case — a gold
# bank on peg defence ignores pi outright.
te_mon_mandate_growth_threshold = {
	value = 4
}

# 1.0 x (pi_core - anchor) — price stability's reaction term (§6).
#
# THE ANCHOR, NOT A LITERAL 2. §9.1 calls the anchor "the mandate target" and
# gives it as 2, or 0 under a metallic regime, which is exactly what
# te_mon_inflation_anchor already holds. Spelling a 2 out here would make a
# gold-standard bank running price stability target r^* - 2 against its own
# pinned zero inflation: permanently 2pp loose, parked at the bottom of the
# gold band, for the one regime whose whole promise is the price LEVEL.
#
# HIDDEN (ruling P7): it reads core inflation, and its consumer adds it to r^*.
te_mon_mandate_price_reaction = {
	value = te_mon_inflation_core_read
	subtract = te_mon_inflation_anchor
	multiply = te_mon_mandate_inflation_weight
}

# 0.5 x max( 0 , pi_core - 4 ) — growth's reaction term (§6). Below the
# threshold it is exactly zero, which is what "runs warm" means and why §6 puts
# the mandate's equilibrium around 3% rather than at target.
#
# HIDDEN, for the same reason as the value above.
te_mon_mandate_growth_reaction_term = {
	value = te_mon_inflation_core_read
	subtract = te_mon_mandate_growth_threshold
	min = 0
	multiply = te_mon_mandate_growth_reaction
}


# --- The premium terms inflation adds (§7.6) --------------------------------

# | expected - anchor |, in pp. change_variable has no absolute value and a
# script value's `limit` tests triggers on the scope rather than on the running
# total, so the sign is decided from the inputs and each branch subtracts the
# other way round — the same shape as te_mon_inflation_gap_abs above.
te_mon_expectation_gap_abs = {
	value = 0
	if = {
		limit = {
			has_variable = te_inflation_expected
			var:te_inflation_expected > te_mon_inflation_anchor
		}
		add = var:te_inflation_expected
		subtract = te_mon_inflation_anchor
	}
	else_if = {
		limit = { has_variable = te_inflation_expected }
		add = te_mon_inflation_anchor
		subtract = var:te_inflation_expected
	}
}

# Unanchored expectations (§7.6, ruling P1): +0.25pp of CYCLICAL premium per pp
# that |expected - anchor| exceeds the 3pp tolerance. Inside the tolerance,
# expectations cost nothing; it is already +3.75pp at expected = 20.
#
# It is one of the three reasons §10's never-disinflate path stays dearer than
# the pre-war baseline instead of becoming the cheapest line in the game — the
# other two are the §9.2 bands and the lenders' floor in step 7.
#
# PUBLIC: expected inflation and the anchor are both displayed exactly.
te_mon_premium_unanchored = {
	value = te_mon_expectation_gap_abs
	subtract = te_mon_unanchored_tolerance
	min = 0
	multiply = te_mon_unanchored_premium_per_pp
}

# Monetisation (§7.6, §11): +0.5pp of cyclical premium per level. Lenders price
# a government that is printing money to pay them, which is half of why
# monetising is not free — the other half is the +2.5pp of inflation pressure
# per level in te_mon_pressure_monetisation.
#
# PUBLIC: the monetisation level is displayed.
te_mon_premium_monetisation = {
	value = 0
	if = {
		limit = { has_variable = te_monetisation_level }
		add = var:te_monetisation_level
	}
	multiply = te_mon_monetisation_premium
}


# --- Display only: the inflation line of the rate-paid sum (§10) ------------

# Headline inflation with its sign flipped, so the Rate You Pay tooltip can
# print the §10 build-up as a column that adds up: market yield, plus credit
# standing, plus risk premium, PLUS this. Rendering `-[...te_inflation...]`
# instead would print "--1.0%" in the deflation band, which is the one band
# where the line is a charge rather than a discount.
#
# Not read by any effect — step 7 subtracts te_inflation directly. PUBLIC:
# headline inflation is displayed exactly.
te_mon_inflation_offset = {
	value = te_mon_inflation_read
	multiply = -1
}
