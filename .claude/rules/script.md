# Script rules: `common/` and `events/`

Loaded when you read or edit a file under `common/` or `events/`. These are the
engine behaviors that have cost the most: each is silent in the log and wrong in
play. The full list is `docs/guides/scripting_best_practices.md`; find the
sections on what you are about to write with
`python3 scripts/lessons.py <effect, trigger or modifier name>`.

Most of these have an audit that catches them. When one flags your change,
`scripts/run_audits.py` prints what the flag means and the comment that
suppresses an intended one; `docs/guides/audits.md` lists all of them.

## The dynamic-modifier scaling pattern

5. **Script values** computing multipliers consumed by `add_modifier { multiplier = ... }`.

## Engine gotchas

- **Before telling the user a vanilla value is engine-hardcoded or missing from the snapshot, scan `vanilla_parsed/common/*.json` by the *effect's* name** (recipe: `docs/guides/python_tools.md`). Tax levels are static modifiers (`tax_modifier_very_low` +10 … `_very_high` −20 legitimacy); a search on guessed key names missed them and the wrong claim reached a PR (#638).
- **The Clausewitz engine silently ignores invalid modifier names and unregistered dynamic patterns.** Validate via `/modifier-search?q=` or `/engine-docs/origin/<name>`. Booleans, building/goods/state-building patterns, and ship axis combos all need explicit registration in `common/modifier_type_definitions/`; a name the engine's `modifiers.log` lists is not registered by that. `modifier_field_audit` catches an unregistered name in any modifier block or `modifier:` read (`--strict` in CI).
- **Top-level entity collisions get silently dropped** (`Duplicated key X will not be created`). Use `INJECT:X = { ... }` to extend rather than redeclare.
- **`add_modifier`/`remove_modifier` results are not visible inside the same effect block.** To recompute from "base" values, store the prior contribution as a variable and subtract from the `modifier:X` read.
- **`short_modifier_time`/`normal_modifier_time`/`long_modifier_time`/`very_long_modifier_time` are days, not months** (off by 30×). And `any_*` triggers don't accept `limit = { }`.
- **`add_modifier`'s `days`/`months` takes a literal or a script value written as a bare `name = N`, never `name = { value = N }` or a computed one**, which it reads as 0 days ("for 0 days" in the tooltip; Planned Capital, 2026-10-23). Every named duration vanilla passes is bare. A computed duration needs a ladder of literals (`un_propose_add_sponsor_mark`). `modifier_duration_audit` catches it, through helpers' `$DAYS$` too (`--strict` in CI).
- **The Clausewitz engine emits no warning for missing loc keys.** A mod-introduced static modifier, journal entry, scripted button, etc. without a corresponding `*_l_english.yml` entry shows the raw key in player UI. `loc_coverage_audit` catches this (`--strict` in CI); check `docs/engine/loc_coverage_report.md` after `/reload`. A modifier field whose type vanilla registers without a name shows the raw key too; `modifier_field_audit` catches that.
- **`country_treaty_leverage_generation_add` generates leverage *against* the country whose modifier block carries it**, not by it — so on a directed treaty article it belongs on the side that does *not* pay `maintenance_paid_by`. Inverting it is engine-silent (valid modifier, valid block, influence just flows the wrong way); monetary phase 6 shipped five articles backwards. An article also builds Involvement only if it declares `max_target_involvement` and `target_involvement_applies_to`, which names the local side, the same side as the leverage line; none of the mod's did until 2026-11-03. `treaty_leverage_side_audit` catches both (`--strict` in CI). Rule and vanilla evidence: `docs/guides/scripting_best_practices.md`.
- **A modifier that takes authority is `country_authority_cost_add = <N>` (positive), never a negative `country_authority_add`.** A negative add lowers *produced* authority, so once that reaches zero the penalties for over-using authority stop applying, and it is scaled by `country_authority_mult` (more multiplier, harder hit); a cost is flat and counts as usage. Engine-silent either way. A shock that reads too weak gets a bigger cost, not a negative add (owner, 2026-10-21, when the last 55 were converted). `test_authority_cost_modifiers.py` fails on one.
- **A company's prestige good needs a roster building that makes its base good.** A company makes it in place of the base good, in its own buildings, so with no `building_types` building producing that good it never appears. An `extension_building_types` building needs an industry charter (one at a time), so it doesn't count. Engine-silent: Google and five other mod companies listed dead prestige goods. A prestige good on a `local = yes` good (electricity, services, transportation, digital access) does nothing either. `prestige_good_roster_audit` catches both (`--strict` in CI).
- **No control in the law panel adds an amendment.** Script attaches it with `add_amendment` (an event option, a journal entry, history); vanilla's enactment negotiation can also have an interest group sponsor one whose `would_sponsor` is true. The mod's rule is that every amendment it defines has a scripted way in, so a sponsor-only one gets an amendment event (`extra_law_events.87`/`.88` are the pattern). An amendment nothing attaches is engine-silent dead content. `amendment_reachability_audit` catches it, and an `add_amendment` whose type names no amendment (`--strict` in CI).
- **An ideology's lawgroup block must name every law in its group.** A law it leaves out is implicitly neutral (a variant, `parent = law_x`, takes its parent's stance instead), so a group that disapproves of the current law backs enacting it. Mod ideologies and blocks the mod adds name every law; a block vanilla had names the laws the mod adds to the group. Add stances in `ideology_modifications.py`; `apply_ideologies.py` writes a vanilla ideology whose changes touch a block vanilla has as a `REPLACE` of its whole entry (it needs the game files to regenerate; `scripts/generators/regen_ideologies_offline.py` replays committed REPLACE bodies without them). Don't `INJECT` a block vanilla's ideology already has: the engine keeps both blocks and the tooltip lists the law group twice. `ideology_lawgroup_audit` catches gaps (`--strict` in CI); `test_apply_ideologies.py` catches a `modified.txt` left stale.
- **Power bloc principle tiers don't stack.** Moving a group from tier III to IV replaces tier III's modifier blocks, so each tier restates every modifier the tier below carried, at its full value. A tier written as a delta takes the missing modifiers away on upgrade with no log line; 62aa550 shipped the education and advanced research ladders that way. `principle_tier_audit` catches it (`--strict` in CI).
- **A visible event with no `event_image` renders a magenta blob, and the engine logs nothing at all** — not even the `VFSOpen Error` line a missing `icon` gets. The default event window has no fallback art; the only supported alternative is a `gui_window` layout with no image panel plus `left_icon`/`right_icon` portraits. `event_image_audit` catches this (`--strict` in CI). Inventory and the `texture`-vs-`video` tradeoff: `docs/guides/event_creation_guide.md`.
- **A revolution's winner inherits the loser's variables, but no modifiers and no variable lists** — not the country's, not the journal entries'. Its own values take precedence, so the loser's value is discarded wherever both held one. Inherited entries (the default) arrive empty and re-run `immediate`, and completed entries start over. So state kept only in a modifier, a list or an unguarded `immediate` set is lost when a revolution wins. The mod's rule is that **the winner continues the nation**: mirror such state in variables and rebuild it (#460–#465). `je_immediate_reset_audit` catches unguarded `immediate` writes (`--strict` in CI). Read from saves: `docs/guides/scripting_best_practices.md` § "What a Civil War's Winner Inherits"; findings in `docs/audits/civil_war_inheritance_audit.md`; compare saves with `scripts/analysis/save_country_probe.py --diff`.
- **A rule-gated journal entry must also end on its rule.** A game rule can be changed mid-game (the screen that changes country), and `disable_evaluation` prunes only inactive records, so an active entry runs on with its modifiers, pulses and events unless its one invalid outcome reads the rule (or it deactivates on it), and what the system put outside the entry needs a teardown of its own (Workshop report, Banking, 2026-11-08). `test_journal_entry_shape.py` fails on a rule-pruned entry that doesn't, unless `# REVIEWED YYYY-MM-DD (rule_outlives): rationale` sits on its `disable_evaluation = {` line (the culture merges pause). Per-system teardowns: `docs/testing/rules-off-midgame-playtest.md`.
- **`change_variable` / `set_variable` render nothing in an option's tooltip.** An option that moves a number the UI displays (a JE's command reliability, a panel's credibility) must say so in `custom_tooltip = { text = <key> <effects> }`, or it reads as "costs money and does nothing" — `nuclear_incident.40` shipped that way. `silent_variable_audit` catches it (`--strict` in CI).
- **A scripted effect or trigger call must pass exactly the `$X$` names its callee's body uses.** An argument the body never names (`failed for unknown arguments`; `should have no arguments` when it names none) or a `$X$` the call leaves out (`failed for missing arguments`) fails the engine's per-call compile at every load, and the call can't be trusted to run. An argument's value is one token: a `{ }` block there (`VALUE = { value = 5000 max = x }`) loses the file's brace count, and every event after it in the file is dropped (#1096); pass a script value. A dispatcher (`helper_$KIND$ = { … }`) passes the same arguments to every kind, so each kind must name them all. `script_argument_audit` catches it (`--strict` in CI); `GET /script-args/<helper>` lists every caller's arguments before you change a signature (#732).

## Conventions

- Brace-based Paradox files use **tab** indentation. Run `python3 scripts/format_paradox_tabs.py <files>` after large edits.
- **A static modifier script adds without a duration needs a line in `scripts/generators/gen_nation_tab.py`'s registry** (a Nation tab section, a row, `KEEP_IN_LIST` or `NOT_ON_COUNTRY`), then a rerun of the generator; `test_nation_tab.py` names any that has none.
- **Never hand-edit auto-generated files.** Always edit the generator's input and re-run. Full ownership map: `docs/auto_generated_files.md`. Quick check while exploring: `git grep -l "AUTO-GENERATED\|do not edit manually" common/ map_data/ localization/`.
- After editing mod files, `POST /reload` to refresh the server's view, and read the response's `warnings` array before calling the change clean.
